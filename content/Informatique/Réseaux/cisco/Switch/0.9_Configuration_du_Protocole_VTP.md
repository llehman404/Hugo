#  Protocole VTP (VLAN Trunking Protocol)

&nbsp;

Le protocole **VTP** permet d’**automatiser la création et la diffusion des VLAN** entre plusieurs switches Cisco.  
Il évite de devoir configurer manuellement les mêmes VLAN sur chaque équipement.

&nbsp;

## Modes VTP

Il existe **3 modes** dans VTPv2 et VTPv3 :

| **Mode** | **Peut créer/modifier/supprimer des VLANs localement ?** | **Propage les mises à jour VTP ?** | **Reçoit et applique les mises à jour VTP ?** | **Transmet les mises à jour VTP (relais) ?** | **Base de données VLAN** |
| --- | --- | --- | --- | --- | --- |
| **Serveur** | ✅ Oui (modifications locales) | ✅ Oui | ✅ Oui | ✅ Oui | Synchronisée avec le domaine |
| **Client** | ❌ Non (lecture seule) | ❌ Non | ✅ Oui | ✅ Oui | Synchronisée avec le serveur |
| **Transparent** | ✅ Oui (modifications locales uniquement) | ❌ Non | ❌ Non | ✅ Oui |     |

&nbsp;

### ⚠️⚠️⚠️ **Attention critique avec VTPv2 !**

Dans **VTPv2**, **même en mode Client**, un switch peut **casser tout le réseau** s’il a un **numéro de révision plus élevé** que le serveur VTP actuel.

**Pourquoi ?**  
Le numéro de révision est **incrémenté à chaque modification** (création/suppression de VLAN) sur un **serveur**.  
Si un switch (même en mode **Client**) a un numéro de révision **plus élevé** que le serveur, **il imposera sa base de données VLAN** au serveur lors de la connexion via un trunk.

**Exemple concret :**

- **Switch A (Serveur)** : VLANs 10, 20, 30 (révision = **5**).
- **Switch B (Client)** : Auparavant en mode Serveur avec VLANs 40, 50 (révision = **10**).
- Tu branches Switch B en mode **Client** sans réinitialiser sa base VTP.
- **Switch B (révision 10) > Switch A (révision 5)** → Switch A **supprime ses VLANs 10,20,30** et adopte ceux de Switch B (40,50).
- **Ton réseau est cassé** ❌.

**Solution obligatoire avant de brancher un switch (même en Client) :**

1.  **Isoler le switch** du réseau (déconnecter le trunk).
2.  Passer en mode **Transparent** :

```cisco
 Switch(config)# vtp mode transparent
```

3.  **Réinitialiser sa base VTP** :

```cisco
 Switch(config)# delete vtp
```

4.  Reconfigurer en mode **Client** avec le bon domaine/mot de passe :

```cisco
 Switch(config)# vtp mode client
 Switch(config)# vtp domain MonReseau
 Switch(config)# vtp password secret123
```

5.  **Brancher le trunk** uniquement après ces étapes.

> **💡 Note sur VTPv3 :**  
> En **VTPv3**, un seul serveur est autorisé à initialiser des mises à jour, ce qui évite ces problèmes. De plus, VTPv3 permet de désactiver le mode Serveur sur un switch.

## Interconnexion des Switches avec Trunk

&nbsp;

### Rôle du Trunk

Le protocole **802.1Q** permet à un **port trunk** de transporter le trafic de **plusieurs VLAN** simultanément entre deux équipements (switches, routeurs).  
**Le VTP utilise les ports trunk** pour propager les mises à jour entre les switches.

> **⚠️ Important :**  
> Sans trunk, les switches **ne peuvent pas échanger les informations VTP** et les VLAN ne seront pas synchronisés.

&nbsp;

### Schéma d’Interconnexion

Schéma d’interconnexion VTP et Trunk  
*Schéma : Switch Serveur VTP (à gauche) et Switch Client VTP (à droite) connectés via un lien trunk.*

&nbsp;

### Commandes de Configuration

**1\. Configuration d’un Port Trunk**

```cisco
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20,30
Switch(config-if)# no shutdown
Switch(config-if)# exit
```

**2\. Configuration d’un Switch en Mode VTP Serveur**

```cisco
Switch(config)# vtp domain MonReseau
Switch(config)# vtp mode server
Switch(config)# vtp password secret123
Switch(config)# vtp version 2
```

&nbsp;

### 🔍 Vérifications Utiles

Pour vérifier la configuration VTP et Trunk :

```cisco
# Vérifier l'état VTP
Switch# show vtp status

# Vérifier les ports trunk
Switch# show interface trunk

# Vérifier les VLANs configurés
Switch# show vlan brief
```

&nbsp;

### 💡 Bonnes Pratiques

1.  **Trunk** :

- Limitez les VLAN autorisés sur un trunk avec `switchport trunk allowed vlan` pour des raisons de **sécurité**.
- Changez le **VLAN natif** (par défaut VLAN 1) pour éviter les attaques : `Switch(config-if)# switchport trunk native vlan 99`

2.  **VTP** :

- Utilisez **VTPv3** si votre matériel le supporte.
- **Désactivez VTP** si vous n’en avez pas besoin : `Switch(config)# vtp mode off`
