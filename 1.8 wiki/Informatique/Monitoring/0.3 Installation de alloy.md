# Install Alloy

> ⚠️ **Prérequis** : Loki installé et démarré sur la même machine (voir fiche *Loki*)

## Installation

```bash
sudo apt install alloy
```

## Vérifier les permissions de lecture

Alloy tourne avec son propre utilisateur (`alloy`), pas en root. Pour lire les  
logs écrits par rsyslog en `0640 root:adm`, il doit être dans le groupe `adm` :

```bash
# Sous quel utilisateur Alloy tourne :
ps -o user= -C alloy

# Vérifier la présence du groupe adm :
id alloy
```

Si `adm` n'apparaît pas dans la liste :

```bash
sudo usermod -aG adm alloy
sudo systemctl restart alloy
```

Sans ça, Alloy démarre sans erreur visible mais ne lit aucun fichier  
(« permission denied » dans ses logs).

## Configuration

```bash
sudo micro /etc/alloy/config.alloy
```

```alloy
// Sample config for Alloy.
//
// For a full configuration reference, see https://grafana.com/docs/alloy

logging {
  level = "warn"
}

// Prometheus scraping (metrics locales + self-scrape d'Alloy)
// NOTE : forward_to est vide -> les métriques sont scrapees mais non
// envoyees nulle part. Ajouter un prometheus.remote_write si on veut
// les stocker, sinon ce bloc est optionnel.

prometheus.exporter.unix "default" {
  include_exporter_metrics = true
  disable_collectors       = ["mdadm"]
}

prometheus.scrape "default" {
  targets = array.concat(
    prometheus.exporter.unix.default.targets,
    [{
      // Self-collect metrics
      job         = "alloy",
      __address__ = "127.0.0.1:12345",
    }],
  )

  forward_to = [
  // TODO: components to forward metrics to (like prometheus.remote_write or
  // prometheus.relabel).
  ]
}

// 1. Find log files on the host

local.file_match "local_files" {
  path_targets = [
    { __path__ = "/var/log/remote/*.log" },
    { __path__ = "/var/log/barsamin/*.log" },
  ]
  sync_period = "5s"
}

// 2. Tail and read the matched log files

loki.source.file "log_scrape" {
  targets       = local.file_match.local_files.targets
  forward_to    = [loki.write.grafana_loki.receiver]
  tail_from_end = true
}

// 3. Define the Loki destination endpoint

loki.write "grafana_loki" {
  endpoint {
    url = "http://localhost:3100/loki/api/v1/push"
  }
}
```

### Labels : deux options

Alloy indexe les logs avec les labels définis dans les `path_targets`. Deux  
façons de faire, au choix :

#### Option A — Simple : garder le label `filename` par défaut

Avec les `path_targets` « nus », Alloy ajoute automatiquement un seul label :  
`filename` (le chemin complet du fichier). Suffisant tant qu'on se souvient à  
quoi correspond chaque chemin.

```alloy
local.file_match "local_files" {
  path_targets = [
    { __path__ = "/var/log/remote/*.log" },
    { __path__ = "/var/log/barsamin/*.log" },
  ]
  sync_period = "5s"
}
```

Requête Grafana : `{filename="/var/log/remote/mihr.log"}`

#### Option B — Labels personnalisés pour filtrer plus facilement

On enrichit chaque `path_targets` avec des attributs en plus, qui deviennent  
autant de labels Loki :

```alloy
local.file_match "local_files" {
  path_targets = [
    { __path__ = "/var/log/remote/*.log",   host = "remote",   source = "rsyslog" },
    { __path__ = "/var/log/barsamin/*.log", host = "barsamin", source = "local" },
  ]
  sync_period = "5s"
}
```

Requête Grafana : `{source="rsyslog"}` — plus court, plus lisible, et le  
label reste valide même si on déplace les fichiers (contrairement à  
`filename`, qui contient le chemin en dur).

> 📝 **Note** : on peut cumuler autant d'attributs qu'on veut  
> (`source`, `host`, `env`...). Les labels sont indexés : privilégier un  
> petit nombre de labels à faible cardinalité (peu de valeurs différentes),  
> jamais le contenu des logs (ex. une IP par log = explosion de l'index).

## Démarrage / vérification

```bash
# Valider la config avant de (re)demarrer :
sudo alloy validate /etc/alloy/config.alloy

sudo systemctl enable --now alloy
sudo systemctl restart alloy

sudo systemctl status alloy

# Erreurs eventuelles (permission denied, push failed...) :
sudo journalctl -u alloy -n 50 --no-pager

# Labels reellement recus par Loki :
curl -s http://localhost:3100/loki/api/v1/labels
```

Côté Grafana : *Explore* → sélectionner la source Loki → requêter  
`{filename="/var/log/remote/mihr.log"}` (ou `{source="rsyslog"}` si les  
labels ont ete ajoutes).
