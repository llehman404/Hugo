#nix #langage #linux

* * *

Le langage **[Nix](https://blog.stephane-robert.info/docs/admin-serveurs/linux/nix/)** est un **langage fonctionnel pur** conçu pour décrire des paquets et des configurations de manière reproductible. Tout y est **expression** : un nombre, une fonction, un fichier de configuration — chaque élément retourne une valeur, rien ne produit d’effet de bord.

Ce guide vous fait découvrir chaque concept fondamental en le testant immédiatement dans le **REPL** ou avec `nix eval`.

* * *

## Ce que vous allez apprendre

- Manipuler les **7 types primitifs** de Nix (entiers, flottants, chaînes, booléens, null, chemins, fonctions).
- Structurer des données avec les **attribute sets** (attrsets) et les **listes**.
- Définir et appeler des **fonctions** (simples, curryfiées, à arguments nommés).
- Utiliser `let...in`, `with`, `inherit` et `if-then-else`.
- Transformer des données avec les **builtins** (`map`, `filter`, `attrNames`, etc.).
- Écrire des expressions complètes prêtes pour `shell.nix` ou `flake.nix`.

* * *

## Dans quel contexte ?

Le langage Nix est le socle de tout l’écosystème :

- Chaque paquet est décrit par une **expression Nix**.
- Chaque `shell.nix`, `flake.nix`, ou module **[NixOS](https://blog.stephane-robert.info/docs/securiser/os-immuable/nixos/)** est du code Nix.

Comprendre le langage vous permet de :

- **Lire et modifier** les fichiers `shell.nix` ou `flake.nix` de vos projets.
- **Écrire vos propres dérivations** pour empaqueter des logiciels.
- **Déboguer** un environnement de développement.
- **Comprendre les exemples** de la documentation `nixpkgs` et NixOS.
- **Personnaliser** une configuration NixOS module par module.

* * *

## Le REPL : votre terrain d’expérimentation

Le **REPL** (Read-Eval-Print Loop) est un terminal interactif pour tester des expressions Nix.  
Lancez-le avec :

```bash
nix repl --expr '{}'
```

→ Tapez une expression, Nix l’évalue et affiche le résultat. Tapez `:q` pour quitter.

Vous pouvez aussi évaluer des expressions ponctuelles directement dans le terminal avec :

```bash
nix eval --expr '1 + 2'
```

**Résultat :**

```
3
```

> **Tous les exemples de ce guide sont testables** avec le REPL ou `nix eval`.

* * *

## Types primitifs

Nix possède **7 types de base**. Vous pouvez vérifier le type de n’importe quelle valeur avec `builtins.typeOf`.

* * *

### Entiers et flottants

```bash
nix eval --expr '1 + 2'
```

**Résultat :**

```
3
```

```bash
nix eval --expr '7 / 2'
```

**Résultat :**

```
3
```

> **Note** : La division entre entiers est **entière** (troncature, pas d’arrondi).

Pour obtenir un résultat décimal :

```bash
nix eval --expr '7.0 / 2.0'
```

**Résultat :**

```
3.5
```

```bash
nix eval --expr 'builtins.typeOf 42'
```

**Résultat :**

```
"int"
```

* * *

### Chaînes de caractères

Les chaînes sont délimitées par des **guillemets doubles** :

```bash
nix eval --expr '"hello" + " world"'
```

**Résultat :**

```
"hello world"
```

> L’opérateur `+` **concatène** les chaînes (et additionne les nombres — Nix distingue par le type des opérandes).

* * *

#### Interpolation avec `${}`

```bash
nix eval --expr 'let name = "Nix"; in "Hello ${name}"'
```

**Résultat :**

```
"Hello Nix"
```

Pour interpoler un nombre, convertissez avec `toString` :

```bash
let port = 8080; in "Port: ${toString port}"
```

**Résultat :**

```
"Port: 8080"
```

* * *

#### Chaînes multilignes

Délimitées par **deux apostrophes simples** (`''`) :

```nix
''
  Première ligne
  Deuxième ligne
''
```

> **Note** : L’indentation minimale commune est **automatiquement supprimée**.

* * *

### Booléens

```bash
nix eval --expr 'true && false'
```

**Résultat :**

```
false
```

```bash
nix eval --expr 'true || false'
```

**Résultat :**

```
true
```

**Opérateurs de comparaison** : `==`, `!=`, `<`, `>`, `<=`, `>=`.

```bash
nix eval --expr '3 > 2'
```

**Résultat :**

```
true
```

* * *

### Null et chemins

```nix
null       # type "null" — absence de valeur
/tmp       # type "path" — chemin absolu
./.        # type "path" — chemin relatif
```

> **Note** :  
> Les **chemins** sont un type à part entière en Nix (pas des chaînes).  
> Un chemin relatif comme `./config.nix` est résolu **par rapport au fichier qui le contient**.  
> C’est ce qui rend `import ./config.nix` **fiable**.

* * *

### Récapitulatif des types

| Type | Exemples | `builtins.typeOf` |
| --- | --- | --- |
| Entier | `42`, `-1`, `0` | `"int"` |
| Flottant | `3.14`, `7.0` | `"float"` |
| Chaîne | `"hello"`, `''multi''` | `"string"` |
| Booléen | `true`, `false` | `"bool"` |
| Null | `null` | `"null"` |
| Chemin | `/tmp`, `./file.nix` | `"path"` |
| Fonction | `x: x + 1` | `"lambda"` |

## Listes

Les listes sont des **collections ordonnées**, délimitées par des crochets et séparées par des **espaces** (pas de virgules) :

```nix
[ 1 2 3 ]
[ "hello" true 42 ]  # types mixtes autorisés
```

* * *

### Opérations sur les listes

```bash
nix eval --expr 'builtins.length [ 1 2 3 ]'
```

**Résultat :**

```
3
```

```bash
nix eval --expr 'builtins.head [ 10 20 30 ]'
```

**Résultat :**

```
10
```

```bash
nix eval --expr 'builtins.tail [ 10 20 30 ]'
```

**Résultat :**

```
[ 20 30 ]
```

```bash
nix eval --expr '[ 1 2 ] ++ [ 3 4 ]'
```

**Résultat :**

```
[ 1 2 3 4 ]
```

> L’opérateur `++` **concatène** deux listes.

**Test d’appartenance** avec `builtins.elem` :

```bash
nix eval --expr 'builtins.elem 3 [ 1 2 3 ]'
```

**Résultat :**

```
true
```

## Attribute sets (attrsets)

L’**attribute set** (ou **attrset**) est la **structure de données fondamentale** de Nix — un dictionnaire clé-valeur.  
Chaque attribut se termine par un `;` :

```nix
{
  name = "Alice";
  age = 30;
  active = true;
}
```

* * *

### Accès et manipulation

```bash
nix eval --expr '{ a = 1; b = 2; }.a'
```

**Résultat :**

```
1
```

* * *

### Fusion avec `//`

L’opérateur `//` **fusionne** deux attrsets. Les clés du côté **droit** écrasent celles du côté **gauche** :

```bash
nix eval --expr '{ a = 1; b = 2; } // { b = 99; c = 3; }'
```

**Résultat :**

```
{ a = 1; b = 99; c = 3; }
```

* * *

### Introspection

```bash
nix eval --expr 'builtins.attrNames { z = 1; a = 2; m = 3; }'
```

**Résultat :**

```
[ "a" "m" "z" ]
```

> Les noms sont retournés **triés alphabétiquement**.

```bash
nix eval --expr 'builtins.attrValues { a = 10; b = 20; }'
```

**Résultat :**

```
[ 10 20 ]
```

* * *

### Test d’existence avec `?`

```bash
nix eval --expr '{ a = 1; } ? a'
```

**Résultat :**

```
true
```

```bash
nix eval --expr '{ a = 1; } ? b'
```

**Résultat :**

```
false
```

**Combiné avec `or` pour une valeur par défaut :**

```nix
let config = { port = 8080; };
in config.host or "localhost"
```

**Résultat :**

```
"localhost"
```

* * *

### Attrsets récursifs avec `rec`

Un attrset **normal** ne peut pas référencer ses propres attributs.  
Avec `rec`, il le peut :

```nix
rec {
  name = "hello";
  fullName = "${name}-world";  # utilise 'name' du même attrset
}
```

**Résultat :**

```
{ name = "hello"; fullName = "hello-world"; }
```

> **⚠️ Attention** :  
> Utilisez `rec` avec **parcimonie**. Il peut créer des **dépendances circulaires** difficiles à déboguer.  
> Préférez `let...in` quand c’est possible.

## Fonctions

En Nix, les **fonctions sont des valeurs comme les autres**.  
La syntaxe est `argument: corps` — le `:` sépare l’argument du corps.

* * *

### Fonctions simples

```bash
nix eval --expr '(x: x * 2) 5'
```

**Résultat :**

```
10
```

> La fonction `x: x * 2` prend un argument `x` et retourne `x * 2`.  
> On l’appelle en lui passant `5` **juste après**.

* * *

### Fonctions curryfiées (plusieurs arguments)

Nix ne supporte **qu’un argument par fonction**.  
Pour plusieurs arguments, on **chaîne les fonctions** :

```bash
nix eval --expr '(a: b: a + b) 3 4'
```

**Résultat :**

```
7
```

> `a: b: a + b` est en réalité `a: (b: a + b)` — une fonction qui retourne une fonction.

* * *

### Fonctions à arguments nommés (pattern matching)

C’est la **forme la plus courante** dans les fichiers Nix.  
L’argument est un **attrset destructuré** :

```bash
nix eval --expr '({ name, age }: "${name} a ${toString age} ans") { name = "Alice"; age = 30; }'
```

**Résultat :**

```
"Alice a 30 ans"
```

* * *

### Valeurs par défaut avec `?`

```nix
{ name, port ? 8080 }:
  "Server ${name} on port ${toString port}"
```

> Si `port` n’est pas fourni, la valeur `8080` est utilisée.

* * *

### Arguments supplémentaires avec `...`

```nix
{ name, port ? 8080, ... }:
  "Server ${name}"
```

> Le `...` autorise l’appelant à passer des **attributs supplémentaires** sans erreur.

> **Astuce** :  
> La syntaxe `{ pkgs ? import <nixpkgs> {} }:` que vous voyez dans presque tous les fichiers `shell.nix` est exactement cette forme :  
> une fonction qui attend un attrset avec un attribut `pkgs` ayant une **valeur par défaut**.

## Variables locales : `let...in`

Le bloc `let...in` crée des **variables locales immuables** :

```bash
nix eval --expr 'let x = 5; y = 3; in x + y'
```

**Résultat :**

```
8
```

**Les variables peuvent se référencer mutuellement** :

```nix
let
  base = 10;
  double = base * 2;
  triple = base * 3;
in
  double + triple
```

**Résultat :**

```
50
```

> **Note** :  
> Les variables Nix sont **immuables**.  
> Une fois définies, elles ne changent **jamais**.  
> Il n’y a pas d’affectation comme `x = x + 1`.  
> C’est une **garantie de reproductibilité**.

* * *

* * *

## `with` — importer un scope

Le mot-clé `with` **importe tous les attributs** d’un attrset dans le scope courant :

```bash
nix eval --expr 'let s = { a = 1; b = 2; }; in with s; a + b'
```

**Résultat :**

```
3
```

**Usage typique** : Éviter de répéter `pkgs.` :

```nix
# Sans with
packages = [ pkgs.git pkgs.vim pkgs.ripgrep ];

# Avec with
packages = with pkgs; [ git vim ripgrep ];
```

> **⚠️ Attention** :  
> `with` peut **polluer le scope** et causer des conflits de noms.  
> Préférez `inherit` pour plus de clarté.

* * *

* * *

## `inherit` — raccourci d’assignation

`inherit` **copie des variables** du scope englobant dans un attrset :

```bash
nix eval --expr 'let x = 1; y = 2; in { inherit x y; }'
```

**Résultat :**

```
{ x = 1; y = 2; }
```

> `inherit x y;` est **strictement équivalent** à `x = x; y = y;`.

**On peut aussi hériter depuis un autre attrset** :

```nix
let config = { port = 8080; host = "localhost"; };
in { inherit (config) port host; }
```

**Résultat :**

```
{ port = 8080; host = "localhost"; }
```

* * *

* * *

## Conditionnels : `if-then-else`

En Nix, `if` est une **expression** qui **retourne toujours une valeur** :

```bash
nix eval --expr 'if 3 > 2 then "oui" else "non"'
```

**Résultat :**

```
"oui"
```

> **⚠️ Important** :  
> Le `else` est **obligatoire** — toute expression doit retourner une valeur.

**Usage typique** : Paquets conditionnels.

```nix
let
  debugMode = true;
  debugTools = if debugMode then [ pkgs.htop pkgs.ncdu ] else [];
in
  basePackages ++ debugTools
```

* * *

* * *

## `import` — charger un fichier Nix

`import` **charge et évalue** un fichier `.nix` :

```nix
# Si config.nix contient { port = 8080; host = "localhost"; }
let config = import ./config.nix;
in config.port
```

**Résultat :**

```
8080
```

**Si le fichier importé est une fonction**, il faut l’appeler avec ses arguments :

```nix
# Si tools.nix contient { pkgs }: [ pkgs.git pkgs.vim ]
let tools = import ./tools.nix { inherit pkgs; };
in tools
```

> **Note** :  
> `<nixpkgs>` est un **chemin spécial** résolu via les channels ou le registre.  
> `import <nixpkgs> {}` retourne l’attrset gigantesque contenant **tous les paquets**.

## Builtins : fonctions intégrées

Nix fournit des **fonctions intégrées** dans l’objet `builtins`.  
Voici les plus utiles :

* * *

### `map` — transformer une liste

```bash
nix eval --expr 'map (x: x * 2) [ 1 2 3 4 ]'
```

**Résultat :**

```
[ 2 4 6 8 ]
```

* * *

### `builtins.filter` — filtrer une liste

```bash
nix eval --expr 'builtins.filter (x: x > 2) [ 1 2 3 4 5 ]'
```

**Résultat :**

```
[ 3 4 5 ]
```

* * *

### Autres builtins utiles

| Builtin | Usage | Exemple |
| --- | --- | --- |
| `builtins.length` | Taille d’une liste | `builtins.length [ 1 2 3 ]` → `3` |
| `builtins.head` | Premier élément | `builtins.head [ 10 20 ]` → `10` |
| `builtins.tail` | Liste sans le premier | `builtins.tail [ 10 20 30 ]` → `[ 20 30 ]` |
| `builtins.elem` | Appartenance | `builtins.elem 3 [ 1 2 3 ]` → `true` |
| `builtins.attrNames` | Clés d’un attrset | `builtins.attrNames { a = 1; }` → `[ "a" ]` |
| `builtins.attrValues` | Valeurs d’un attrset | `builtins.attrValues { a = 1; }` → `[ 1 ]` |
| `builtins.hasAttr` | Test d’attribut | `builtins.hasAttr "a" { a = 1; }` → `true` |
| `toString` | Conversion en chaîne | `toString 42` → `"42"` |
| `builtins.typeOf` | Type d’une valeur | `builtins.typeOf 42` → `"int"` |

## Mettre tout ensemble : anatomie d’un `shell.nix`

Voici comment les concepts se combinent dans un fichier `shell.nix` typique :

`**shell.nix` 😗\*

```nix
{ pkgs ? import <nixpkgs> {} }:    # ← fonction à argument nommé + défaut

let
  projectName = "mon-api";         # ← variable locale

  # Fonction lambda pour ajouter des paquets Python
  pythonEnv = pkgs.python312.withPackages (ps: [
    ps.requests
    ps.flask
  ]);

  debugMode = true;

  # Conditionnel pour ajouter des outils de debug
  debugTools = if debugMode
    then [ pkgs.htop pkgs.ncdu ]
    else [];
in
pkgs.mkShell {
  name = "${projectName}-dev";     # ← interpolation

  # Utilisation de `with` pour éviter de répéter `pkgs.`
  packages = with pkgs; [
    pythonEnv
    git
    vim
  ] ++ debugTools;                 # ← concaténation de listes

  PROJECT_NAME = projectName;      # ← variable d'environnement
}
```

> **Chaque ligne** utilise un concept que vous venez d’apprendre.

## À retenir

- **Tout est expression** en Nix : il n’y a pas d’instructions, chaque élément retourne une valeur.
- Les **attrsets** (`{ clé = valeur; }`) sont la **structure universelle** — les paquets, les configurations, les modules sont tous des attrsets.
- Les **fonctions** sont omniprésentes : chaque fichier `.nix` est généralement une fonction qui attend `pkgs` ou d’autres arguments.
- Les variables sont **immuables** : une fois définies dans un `let`, elles ne changent plus.
- `**with**`, `**inherit**` et `**//**` sont des **raccourcis syntaxiques** qui rendent le code plus lisible — ils ne sont pas obligatoires mais très courants.
- Le **REPL** (`nix repl`) et `nix eval --expr` sont vos **meilleurs alliés** pour expérimenter.
