# 📘 Fiche DHCP Windows Server (PowerShell)

> Commandes de référence pour installer, configurer, redonder et dépanner un serveur DHCP sous Windows Server.

* * *

## 1\. Installation du rôle DHCP

```powershell
# Installer le rôle + les outils d'administration (cmdlets)
Install-WindowsFeature DHCP -IncludeManagementTools

# Vérifier l'installation
Get-WindowsFeature DHCP
Get-Service dhcpserver
```

## 2\. Redémarrer le service DHCP

```powershell
Restart-Service DHCPServer -Force
```

## 3\. Autoriser le serveur dans Active Directory

> ⚠️ Obligatoire sur un réseau domainé : un serveur DHCP non autorisé est automatiquement mis en pause par Windows (détection rogue DHCP).

```powershell
Add-DhcpServerInDC -DnsName "SRV01.GreenTechSprint.fr" -IPAddress 192.168.60.1

# Vérifier les serveurs autorisés
Get-DhcpServerInDC
```

## 4\. Créer une étendue (scope) et ses options

```powershell
Add-DhcpServerv4Scope `
    -Name "Users" `
    -StartRange 192.168.60.1 `
    -EndRange 192.168.60.254 `
    -SubnetMask 255.255.255.0 `
    -State Active

# Options du scope : domaine, DNS, passerelle
Set-DhcpServerv4OptionValue `
    -ScopeId 192.168.60.0 `
    -DnsDomain "GreenTechSprint.fr" `
    -DnsServer 192.168.60.1 `
    -Router 192.168.60.254
```

## 5\. Script : création d’étendues en boucleS

```powershell
$reseaux = @(
    @{ res = 10; nom = "Ressources humaines" },
    @{ res = 20; nom = "Comptabilité" },
    @{ res = 30; nom = "Informatique" },
    @{ res = 40; nom = "Direction générale" },
    @{ res = 50; nom = "Design-Animation" },
    @{ res = 60; nom = "Serveurs" }
)

foreach ($reseau in $reseaux) {
    $res = $reseau.res
    $nom = $reseau.nom
    Add-DhcpServerv4Scope -Name $nom `
        -StartRange 10.0.$res.1 -EndRange 10.0.$res.254 `
        -SubnetMask 255.255.255.0 -State Active
    Set-DhcpServerv4OptionValue -ScopeId 10.0.$res.0 `
        -DnsDomain "CreativeFusion-Studios.eu" `
        -DnsServer 10.0.60.10 `
        -Router 10.0.$res.254
}
```

# 🔁 Serveur DHCP redondant (failover)

## Principe

Une **relation de failover** est un objet partagé entre deux serveurs DHCP qui réplique les baux d’une ou plusieurs étendues. Deux modes :

| Mode | Fonctionnement | Paramètre clé |
| --- | --- | --- |
| **HotStandby** | Un actif sert 100 % des requêtes, l’autre attend en secours | `-ServerRole Active/Standby`, `-ReservePercent` |
| **LoadBalance** | Les deux serveurs se partagent les requêtes (hash MAC du client) | `-LoadBalancePercent` |

### Créer la relation (splatting avec commentaires)

```powershell
$failover = @{
    ComputerName         = "Baal.Loupulus.org"   # Serveur sur lequel s'applique la commande
    Name                 = "Loupulus_failover"   # Nom de la relation (étiquette administrative)
    PartnerServer        = "Anahit.Loupulus.org" # Le partenaire (l'autre bout de la relation)
    ServerRole           = "Active"              # Rôle du serveur ComputerName : Active ou Standby
    ScopeId              = "192.168.10.0"        # Étendue(s) à répliquer
    SharedSecret         = "loupulus.org"        # Secret d'authentification de la réplication
    StateSwitchInterval  = [timespan]"00:02:00"  # Bascule auto après 2 min de silence
    ReservePercent       = 20                    # Réserve d'IP pour le standby (voir note)
    AutoStateTransition  = $true                 # Autorise la transition automatique
}

Add-DhcpServerv4Failover @failover
```

> ⚠️ **Rôles** : `-ServerRole` s’applique au serveur désigné par `-ComputerName`. Pour inverser les rôles d’une relation existante, il n’y a **pas de commande directe** → supprimer et recréer la relation (voir § Modification).

> 📌 **ReservePercent** : pourcentage d’adresses libres que le primaire ne distribuera jamais, réservé au standby pour servir les nouveaux clients pendant une panne sans risque de conflit d’adresses. Défaut : 5 %. N’existe qu’en HotStandby (inutile en LoadBalance, les deux serveurs étant toujours actifs).

> 📌 **SharedSecret** : en production, éviter de le taper en clair (historique PowerShell) → `$s = Read-Host -AsSecureString`.

# ✏️ Modifier un failover / load balancing existant

La cmdlet **`Set-DhcpServerv4Failover`** modifie les **paramètres de fonctionnement** de la relation. Elle ne peut **pas** modifier son identité (rôles, partenaire, nom) ni supprimer quoi que ce soit.

## Paramètres modifiables

| Paramètre | Type | Signification |
| --- | --- | --- |
| `-Name` | string | **Obligatoire** : identifie la relation à modifier |
| `-Mode` | HotStandby / LoadBalance | **Change le mode de la relation** |
| `-LoadBalancePercent` | uint32 | Répartition du trafic (mode LoadBalance) : % pour le serveur local |
| `-ReservePercent` | uint32 | Réserve d’IP du standby (mode HotStandby) |
| `-MaxClientLeadTime` | timespan | Avance de bail accordée par le standby |
| `-AutoStateTransition` | bool | Active/désactive la bascule automatique en PartnerDown |
| `-StateSwitchInterval` | timespan | Délai de silence avant bascule automatique |
| `-PartnerDown` | switch | Déclare manuellement le partenaire mort → le serveur local devient actif |
| `-SharedSecret` | string | Change le secret de réplication |
| `-Force` | switch | Supprime les demandes de confirmation |
| `-ComputerName` | string | Exécute la commande sur un serveur distant |
| `-PassThru` | switch | Renvoie l’objet modifié |

## Exemples de modification

```powershell
# Ajuster la réserve d'adresses du standby
Set-DhcpServerv4Failover -Name "Loupulus_failover" -ReservePercent 10

# Activer la bascule automatique après 2h de silence
Set-DhcpServerv4Failover -Name "Loupulus_failover" `
    -AutoStateTransition $true `
    -StateSwitchInterval 02:00:00

# Rééquilibrer un load balancing (70 % pour le serveur local)
Set-DhcpServerv4Failover -Name "Users" -LoadBalancePercent 70

# Convertir une relation HotStandby → LoadBalance (possible en place !)
Set-DhcpServerv4Failover -Name "Users" -Mode LoadBalance -LoadBalancePercent 50

# Repasser en HotStandby (le serveur local devient l'actif)
Set-DhcpServerv4Failover -Name "Users" -Mode HotStandby -Force

# Changer le secret partagé
Set-DhcpServerv4Failover -Name "Users" -SharedSecret "NouveauSecret"

# Bascule manuelle d'urgence : déclarer le partenaire mort
Set-DhcpServerv4Failover -Name "Loupulus_failover" -PartnerDown

# Version splattée (avec commentaires)
$modifs = @{
    Name                = "Loupulus_failover"   # Relation visée
    ReservePercent      = 10                    # Nouvelle réserve
    MaxClientLeadTime   = [timespan]"01:00:00"  # Avance de bail
}
Set-DhcpServerv4Failover @modifs
```

## Ajouter / retirer une étendue de la relation

```powershell
# Ajouter un scope à une relation existante
Add-DhcpServerv4FailoverScope -Name "Loupulus_failover" -ScopeId 192.168.11.0

# Retirer un scope de la relation
Remove-DhcpServerv4FailoverScope -Name "Loupulus_failover" -ScopeId 192.168.11.0 -Force
```

## Ce qu’on NE peut PAS modifier en place

| Élément | Solution |
| --- | --- |
| Rôles Active ↔ Standby | `Remove-DhcpServerv4Failover` puis recréer avec les rôles inversés |
| Partenaire (`PartnerServer`) | Remove + recreate |
| Nom de la relation | Remove + recreate |

```powershell
# Procédure d'échange des rôles (sans impact client, les scopes/baux sont conservés)
Remove-DhcpServerv4Failover -Name "Loupulus_failover" -Force
# ... puis Add-DhcpServerv4Failover avec -ServerRole inversé
```

## Les états de la relation (machine à états)

| État | Signification |
| --- | --- |
| `Normal` | Réplication OK, tout va bien |
| `CommunicationsInterrupted` | Le partenaire ne répond plus (cause inconnue) |
| `PartnerDown` | Partenaire déclaré mort → le serveur local sert tout le scope |
| `PotentialConflict` | Split-brain : deux serveurs actifs simultanément ⚠️ |
| `Recovering` | Le partenaire revient, resynchronisation des baux |

```powershell
# Suivre l'état de la relation
Get-DhcpServerv4Failover -Name "Loupulus_failover"

# Vérifier la cohérence côté partenaire
Get-DhcpServerv4Failover -ComputerName "Anahit.Loupulus.org" -Name "Loupulus_failover"
```

# 🔄 Réplication de la configuration (≠ réplication des baux)

## Ce que la relation failover synchronise… ou pas

| Élément | Réplication |
| --- | --- |
| **Baux** (IP ↔ MAC) | ✅ automatique et continue |
| **Création du scope sur le partenaire** | ✅ faite à la création de la relation |
| **Modifications de config ensuite** (options, réservations, exclusions) | ❌ **pas automatiques** → déclencher une réplication de config |
| Options au niveau **serveur** (hors scope) | ❌ jamais répliquées |

> ⚠️ Piège classique : ajouter une option sur un scope du serveur A ne peuple PAS le serveur B. Le failover ne réplique en continu que les baux. Toute modif de config doit être suivie d’un `Invoke-DhcpServerv4FailoverReplication`.

## Propager une modification de configuration

```powershell
# 1. Modifier la config sur le serveur source (ex: ajouter le 2e DNS distribué)
Set-DhcpServerv4OptionValue -ComputerName "Baal.Loupulus.org" `
    -ScopeId 192.168.10.0 -DnsServer 192.168.10.10, 192.168.10.20

# 2. Répliquer la configuration vers le partenaire
Invoke-DhcpServerv4FailoverReplication -Name "Loupulus_failover" -Force

# Ou répliquer un seul scope
Invoke-DhcpServerv4FailoverReplication -ScopeId 192.168.10.0 -Force

# 3. Vérifier la cohérence des deux côtés
Get-DhcpServerv4OptionValue -ComputerName "Baal.Loupulus.org" -ScopeId 192.168.10.0 -OptionId 6
Get-DhcpServerv4OptionValue -ComputerName "Anahit.Loupulus.org" -ScopeId 192.168.10.0 -OptionId 6
```

> ⚠️ La réplication copie **du serveur source vers le partenaire en écrasant**. Se tromper de source = écraser la bonne config avec l’ancienne. En cas de doute : `-WhatIf` d’abord, et ne répliquer qu’un scope ciblé plutôt que toute la relation.

# ⚖️ Serveur de partage de charge (load balancing)

```powershell
# Création d'une relation en LoadBalance (défaut 50/50)
$lb = @{
    ComputerName     = "Barsamin.GreenTechSprint.fr"  # Serveur où s'applique la commande
    Name             = "Users"                        # Nom de la relation
    PartnerServer    = "Vahagan.GreenTechSprint.fr"   # Partenaire
    LoadBalancePercent = 70                           # 70 % pour le serveur local, 30 % pour le partenaire
    ScopeId          = "192.168.60.0"                 # Étendue concernée
    SharedSecret     = "sEcReT"                       # Secret de réplication
}
Add-DhcpServerv4Failover @lb
```

> 💡 En LoadBalance : **pas de `-ServerRole`** (les deux serveurs sont équivalents) et **pas de ReservePercent** (les deux serveurs distribuent en permanence, donc aucun retard à compenser). La répartition se fait par hachage de l’adresse MAC : un client donné parle toujours au même serveur.

```powershell
# Réajuster la répartition
Set-DhcpServerv4Failover -Name "Users" -LoadBalancePercent 70
```

# 🧠 Mémo pièges d’examen

1.  **Échanger les rôles Active/Standby** → impossible en place : remove + recreate
2.  **`-ServerRole`** s’applique au serveur `-ComputerName`, pas au partenaire
3.  **`-Mode` est modifiable** via `Set-` (HotStandby ↔ LoadBalance)
4.  **ReservePercent** = réserve du standby, uniquement en HotStandby
5.  **`-PartnerDown`** = bascule manuelle, sans vérification réelle → risque de split-brain
6.  Un serveur DHCP domainé **non autorisé dans AD** se met en pause tout seul
7.  **La réplication failover ne porte que sur les baux** : les modifs de config (options, réservations) nécessitent `Invoke-DhcpServerv4FailoverReplication`
8.  **Redondance DNS** : chaque DC en `127.0.0.1` + partenaire en 2e, et les DEUX DNS dans les options du scope pour les clients
