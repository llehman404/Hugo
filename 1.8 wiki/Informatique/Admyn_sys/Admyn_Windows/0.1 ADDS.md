# 🌲 Fiche AD DS &amp; DNS — Windows Server (PowerShell)

> Commandes de référence pour préparer, installer, promouvoir, redonder et vérifier Active Directory Domain Services et le DNS associé.

---

## 1. Préparer le serveur (AVANT tout rôle)

### Changer le hostname

```powershell
Rename-Computer -NewName "Anahit" -Restart    # le redémarrage applique le nom
```

> ⚠️ Le hostname doit être appliqué **avant** la promotion en DC. Un `Install-ADDS*` sur un serveur au nom temporaire (WIN-XXXX) est un classique d'échec.

### Définir une adresse IP fixe

```powershell
# Repérer la carte et son index
Get-NetAdapter
Get-NetIPInterface

# Configurer (adapter l'index à VOTRE machine)
New-NetIPAddress -InterfaceIndex 12 `
    -IPAddress 10.10.10.1 `
    -PrefixLength 24 `
    -DefaultGateway 10.10.10.254
```

> ⚠️ Un DC doit **toujours** avoir une IP fixe. Un DC en DHCP = karma négatif assuré (enregistrements DNS instables, réplication cassée).

### Configurer les serveurs DNS

**Cas A — Futur PREMIER DC (création de forêt)** : peu importe pour l'instant, la promotion installera le DNS local.

```powershell
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 127.0.0.1
```

**Cas B — Futur SECOND DC (rejoindre un domaine)** : pointer vers le DNS du DC **existant**, **uniquement**.

```powershell
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 192.168.10.10   # IP du DC existant
```

> 🚨 **Piège n°1 des échecs de promotion** : un futur 2e DC qui pointe sur `127.0.0.1` (ou un DNS public) **ne peut pas résoudre le domaine** → `Install-ADDSDomainController` échoue. Le `127.0.0.1` ne se met en premier **qu'après** la promotion (voir § 5).

### Vérifier que le DHCP client est désactivé (obligatoire sur un DC)

```powershell
# 1. Vérifier l'état : Dhcp doit être Disabled
Get-NetIPInterface -AddressFamily IPv4 | Select InterfaceAlias, InterfaceIndex, Dhcp

# 2. S'il est encore Enabled → le désactiver
Set-NetIPInterface -InterfaceIndex 12 -Dhcp Disabled
```

## 2. Installer le rôle AD DS

```powershell
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
Import-Module ADDSDeployment
```

> Le rôle seul ne fait rien : il faut ensuite **promouvoir** le serveur (création de forêt ou ajout de DC).

---

## 3. Créer une nouvelle forêt (PREMIER DC)

```powershell
Install-ADDSForest `
    -CreateDnsDelegation:$false `
    -DatabasePath "C:\Windows\NTDS" `
    -DomainMode "WinThreshold" `
    -DomainName "Loupulus.org" `
    -DomainNetbiosName "LOUPULUS" `
    -ForestMode "WinThreshold" `
    -InstallDns:$true `
    -LogPath "C:\Windows\NTDS" `
    -NoRebootOnCompletion:$false `
    -SysvolPath "C:\Windows\SYSVOL" `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "Mot de passe DSRM") `
    -Force:$true
```

**Paramètres à retenir :**


| Paramètre                        | Rôle                                                           |
| -------------------------------- | -------------------------------------------------------------- |
| `-DomainName`                    | FQDN de la forêt (ex: Loupulus.org)                            |
| `-DomainNetbiosName`             | Nom NetBIOS (≤ 15 caractères, pour les clients anciens)        |
| `-InstallDns:$true`              | Installe le DNS + crée la zone intégrée AD                     |
| `-SafeModeAdministratorPassword` | Mot de passe DSRM (mode restauration) — **à ne jamais perdre** |
| `-DomainMode` / `-ForestMode`    | Niveau fonctionnel (`WinThreshold` = 2016+)                    |


> ⚠️ Après installation : redémarrage automatique (sauf `-NoRebootOnCompletion:$true`). Puis configurer le DNS local en `127.0.0.1` (voir § 5).

## 4. Ajouter un contrôleur de domaine supplémentaire (SECOND DC)

> 🎯 C'est ce qui rend l'AD **redondant** : le second DC réplique la base AD **et** héberge un serveur DNS complet (zones intégrées AD répliquées automatiquement).

**Pré-requis critiques :**

1. IP fixe ✅ (§ 1)
2. DNS pointé vers le DC existant, **uniquement** ✅ (§ 1, Cas B)
3. Le DC existant est **allumé et joignable** ✅

```powershell
# 1. Installer le rôle (UNE fois)
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools

# 2. Puis la promotion
Install-ADDSDomainController `
    -CreateDnsDelegation:$false `
    -Credential (Get-Credential "LOUPULUS\Administrateur") `
    -SafeModeAdministratorPassword (Read-Host -AsSecureString "Mot de passe DSRM") `
    -DatabasePath "C:\Windows\NTDS" `
    -DomainName "Loupulus.org" `
    -InstallDns:$true `
    -LogPath "C:\Windows\NTDS" `
    -SiteName "Default-First-Site-Name" `
    -SysvolPath "C:\Windows\SYSVOL" `
    -Force:$true
```

> ⚠️ `-Credential` attend un compte **ayant le droit d'ajouter un DC** (admin du domaine).

### Après la promotion et le redémarrage

```powershell
# Le nouveau DC se met lui-même en premier DNS, l'ancien en second
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 127.0.0.1, 192.168.10.10
```

Attendre la réplication initiale (quelques minutes), puis vérifier :

```powershell
Get-ADDomainController -Filter * | Select Name, IPv4Address, Site
Get-DnsServerZone                      # les zones intégrées AD doivent apparaître
```

## 5. Stratégie DNS des contrôleurs de domaine (après promotion)


| Serveur                   | DNS n°1                | DNS n°2          | Pourquoi                                     |
| ------------------------- | ---------------------- | ---------------- | -------------------------------------------- |
| Premier DC                | `127.0.0.1` (lui-même) | IP du second DC  | Jamais de timeout local ; l'autre en secours |
| Second DC                 | `127.0.0.1` (lui-même) | IP du premier DC | Symétrique                                   |
| Postes clients (via DHCP) | IP du 1er DC           | IP du 2e DC      | Bascule client \~5-15 s                      |


```powershell
# Sur chaque DC : lui-même d'abord (pratique recommandée Microsoft)
Set-DnsClientServerAddress -InterfaceAlias "Ethernet" -ServerAddresses 127.0.0.1, <IP_partenaire>
```

> 🚨 **Récap des pièges DNS selon le stade** :
>
> - **Avant promotion d'un 2e DC** → DNS = IP du DC existant **uniquement**
> - **Après promotion** → DNS = `127.0.0.1` + partenaire
> - Un DC qui pointe vers un DNS **public** (8.8.8.8...) ne résout plus son propre domaine → réplication et authentification cassées

## 6. Vérification

### Santé de la réplication AD

```powershell
# Vue synthétique : les répliques doivent être sans erreur
repadmin /replsummary

# Détail complet des réplications
repadmin /showrepl

# Uniquement les erreurs (le plus utile au quotidien)
repadmin /showrepl /errorsonly

# Forcer une réplication complète dans les deux sens
repadmin /syncall /AdeP
```

### Diagnostic global des DC

```powershell
# Analyse complète d'un DC
dcdiag /s:Barsamin /a

# Uniquement les erreurs
dcdiag /s:Barsamin /q

# Test DNS complet du DC
dcdiag /s:Barsamin /test:dns
```

### Vérification DNS

```powershell
# Outil externe, à télécharger (pas natif) — à placer dans System32
dnslint /ad 192.168.23.1 /s 192.168.23.1 /v

# Natif : zones présentes et intégrées AD
Get-DnsServerZone
Get-DnsServerZone -Name "Loupulus.org" | Select ZoneType, IsDsIntegrated, ReplicationScope

# Le DC répond-il localement ?
Resolve-DnsName Loupulus.org -Server 127.0.0.1

# Le client trouve-t-il un DC ?
nltest /dsgetdc:Loupulus.org
```

### Lister les DC du domaine

```powershell
Get-ADDomainController -Filter * | Select Name, IPv4Address, Site, OperatingSystem
```

## 6bis. Zones DNS — création et arguments

### Les 3 types de zones

| | Principale | Secondaire | Stub |
|---|---|---|---|
| Contenu | Tout | Tout (copie) | **NS** seulement |
| Modifiable ? | ✅ Oui | ❌ Non | ❌ Non |
| Mise à jour | Directement | Transfert de zone | Requêtes aux masters |
| Intégrée AD ? | ✅ Oui | ❌ Non | ✅ Oui |
| Usage | Zone de référence | DNS **non-DC** (DMZ...) | Délégation |

> 🚨 **DC redondants** (ton cas) : **zone principale intégrée AD** — la réplication AD la propage seule aux autres DC. Jamais de zone secondaire entre DC du même domaine (inutile et conflictuel).

### Arguments (un tableau par cmdlet)

| `Add-DnsServerPrimaryZone` | Rôle |
|---|---|
| `-Name` | Zone **directe** (`Loupulus.org`) |
| `-NetworkId "192.168.10.0/24"` | Zone **inversée** (auto : `10.168.192.in-addr.arpa`) — remplace `-Name` |
| `-ZoneFile` | Stockage **fichier** (exclu avec `-ReplicationScope`) |
| `-ReplicationScope Domain/Forest/Legacy/Custom` | Zone **intégrée AD** (exclu avec `-ZoneFile`) |
| `-DirectoryPartitionName` | Avec `Custom` uniquement |
| `-DynamicUpdate Secure` | Mises à jour dynamiques (AD uniquement) |

| `Add-DnsServerSecondaryZone` | Rôle |
|---|---|
| `-ZoneFile` + `-MasterServers` | **Tous deux obligato** : copie locale + IP du serveur source |

| `Add-DnsServerStubZone` | Rôle |
|---|---|
| `-MasterServers` | IP des serveurs faisant autorité — **obligatoire** |
| `-ReplicationScope` ou `-ZoneFile` | Intégrée AD ou fichier |

### Étendues de réplication (`-ReplicationScope`)

| Argument | Répliqué vers... | Usage |
|---|---|---|
| `Domain` | DC du domaine courant | **Standard, 95 % des cas** ✅ |
| `Forest` | DC de **tous** les domaines | Multi-domaines (ex: zone inversée commune) |
| `Legacy` | Tous les DC (compat. W2000) | Musée — jamais en pratique |
| `Custom` | Partition personnalisée | Sur-mesure (rare) |

### Exemple type (zone inversée sur DC redondants)

```powershell
Add-DnsServerPrimaryZone -NetworkId "192.168.10.0/24" -ReplicationScope Domain -DynamicUpdate Secure
Get-DnsServerZone -ComputerName "Anahit.Loupulus.org"   # la zone doit y apparaître seule (réplication AD)
Resolve-DnsName 192.168.10.10        # tester la résolution inversée
```

> 💡 Les PTR ne se créent pas rétroactivement : `ipconfig /registerdns` sur le poste, ou attendre le renouvellement de bail (le DHCP les enregistre par défaut).

## 7. Dépannage express

### Erreur dcdiag / enregistrement DNS manquant (ex: nouveau DC invisible)

```powershell
# 1. Sur le DC concerné : vérifier son enregistrement DNS
Resolve-DnsName ANAHIT.Loupulus.org

# 2. Redémarrer Netlogon (réenregistre les enregistrements SRV/A du DC)
Restart-Service Netlogon -Force

# 3. Forcer l'enregistrement DNS
ipconfig /registerdns

# 4. Forcer une réplication complète dans les deux sens
repadmin /syncall /AdeP

# 5. Re-tester dcdiag depuis l'autre DC
dcdiag /s:Baal /a /q
```

### La promotion du 2e DC échoue — checklist


| Symptôme probable                       | Cause                                       | Remède                                       |
| --------------------------------------- | ------------------------------------------- | -------------------------------------------- |
| "Le domaine n'existe pas" / introuvable | DNS pointe sur `127.0.0.1` ou un DNS public | Pointer sur l'IP du DC existant (§ 1, Cas B) |
| Accès refusé                            | Compte sans droits                          | `-Credential` avec un admin du domaine       |
| Mot de passe DSRM refusé                | Politique de mot de passe (trop faible)     | Mot de passe complexe                        |
| Nom du serveur bizarre (WIN-XXXX)       | Pas de redémarrage après `Rename-Computer`  | Redémarrer avant la promotion                |


### Après extinction du DC principal : tout est lent (plusieurs minutes)

Le résolveur Windows garde le DC mort en tête de DNS et cumule les timeouts, + caches négatifs DNS et tickets Kerberos périmés :

```powershell
# Sur le client
ipconfig /flushdns     # purge le cache DNS
klist purge            # purge les tickets Kerberos
nltest /dsgetdc:Loupulus.org    # force une localisation DC fraîche
```

> 💡 Vérifier aussi que le DC survivant a bien `127.0.0.1` **en premier** dans ses DNS — sinon il timeout sur le mort avant de s'interroger lui-même.

## 8. Mémo pièges d'examen

1. Un DC doit avoir une **IP fixe** et être son **propre DNS principal** (`127.0.0.1` en premier)
2. **Avant** de promouvoir un 2e DC : son DNS = **IP du DC existant uniquement** (pas de `127.0.0.1`, pas de DNS public)
3. `-InstallDns:$true` installe le DNS avec des **zones intégrées AD** → réplication automatique entre DC
4. `Install-ADDSForest` (1er DC) ≠ `Install-ADDSDomainController` (DC supplémentaire)
5. Le **DSRM** (`SafeModeAdministratorPassword`) : mot de passe de restauration, à conserver précieusement
6. Réplication AD/DNS : multimaitre — n'importe quel DC accepte les mises à jour
7. `repadmin /replsummary` et `dcdiag /q` = les réflexes de vérification
8. La redondance AD ne rend pas le DHCP redondant (et inversement) — **chaque rôle a son propre mécanisme**
9. Un client bascule de DNS en \~5-15 s ; les lenteurs "plusieurs minutes" = mauvais ordre DNS + caches
