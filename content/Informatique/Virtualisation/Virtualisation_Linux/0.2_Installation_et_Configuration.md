# Installer KVM/libvirt sur Linux

> *Guide pour créer des machines virtuelles sur un serveur Linux en 15 minutes.*

* * *

## **Quick Path (5 commandes)**

Pour une installation rapide sur **Ubuntu/Debian** ou **RHEL/Rocky/Fedora** :

### Ubuntu/Debian

```bash
# 1. Vérifier le CPU (doit retourner > 0)
egrep -c '(vmx|svm)' /proc/cpuinfo

# 2. Installer les paquets
sudo apt install -y qemu-kvm libvirt-daemon-system libvirt-clients virtinst

# 3. Activer le service
sudo systemctl enable --now libvirtd

# 4. Configurer les permissions
sudo usermod -aG libvirt,kvm $USER && newgrp libvirt

# 5. Tester
virt-host-validate && virsh -c qemu:///system list --all
```

### RHEL/Rocky/Fedora

```bash
# 1. Vérifier le CPU (doit retourner > 0)
egrep -c '(vmx|svm)' /proc/cpuinfo

# 2. Installer les paquets
sudo dnf install -y @virtualization

# 3. Activer le service
sudo systemctl enable --now libvirtd

# 4. Configurer les permissions
sudo usermod -aG libvirt $USER && newgrp libvirt

# 5. Tester
virt-host-validate && virsh -c qemu:///system list --all
```

**Validation** :  
Si `virt-host-validate` affiche **PASS** pour `/dev/kvm` et que `virsh list` ne retourne pas d’erreur, l’installation est réussie.

* * *

## **Ce que vous allez apprendre**

- Vérifier que votre **CPU supporte la virtualisation**.
- Installer les **paquets nécessaires** selon votre distribution.
- Configurer les **permissions** pour gérer les VMs sans `sudo`.
- **Valider l’installation** avec les commandes de diagnostic.

* * *

## **Prérequis**

- Un serveur/PC avec un processeur **Intel VT-x** ou **AMD-V**.
- Un système Linux (**Debian/Ubuntu** ou **RHEL/Rocky/Fedora**).
- Accès **root** ou **sudo**.

> **Rappel** :
> 
> - **KVM** : Accélération matérielle.
> - **QEMU** : Émulateur.
> - **libvirt** : Gestion des VMs.

* * *

## **Étape 1 : Vérifier le support CPU**

KVM nécessite un CPU avec **Intel VT-x** ou **AMD-V**.

### Vérifier les extensions CPU

```bash
egrep -c '(vmx|svm)' /proc/cpuinfo
```

**Résultat attendu** : Un nombre **\> 0** (ex: `4`, `8`).  
Si le résultat est `0` :

1.  Redémarrez et accédez au **BIOS/UEFI**.
2.  Activez **Intel VT-x**, **AMD-V**, ou **Virtualization Technology**.
3.  Sauvegardez et redémarrez.

### Identifier le type de CPU

```bash
grep -E 'vmx|svm' /proc/cpuinfo | head -1
```

| Extension | Fabricant | Module kernel |
| --- | --- | --- |
| `vmx` | Intel | `kvm_intel` |
| `svm` | AMD | `kvm_amd` |

* * *

## **Étape 2 : Installer les paquets**

### Pour **Debian/Ubuntu**

#### Mise à jour du système

```bash
sudo apt update && sudo apt upgrade -y
```

#### Installation des paquets

```bash
sudo apt install -y \
  qemu-kvm \
  libvirt-daemon-system \
  libvirt-clients \
  virtinst \
  virt-manager
```

| Paquet | Rôle |
| --- | --- |
| `qemu-kvm` | QEMU avec accélération KVM |
| `libvirt-daemon-system` | Daemon libvirtd + configuration système |
| `libvirt-clients` | Outils CLI (`virsh`) |
| `virtinst` | Outil `virt-install` pour créer des VMs |
| `virt-manager` | Interface graphique (optionnel) |

> **Note** : `bridge-utils` est obsolète. Utilisez `iproute2` (`ip link`, `bridge`).

#### Vérification avec `kvm-ok` (Ubuntu)

```bash
sudo apt install -y cpu-checker
kvm-ok
```

**Résultat attendu** :

```
INFO: /dev/kvm exists
KVM acceleration can be used
```

* * *

### Pour **RHEL/Rocky/Fedora**

#### Mise à jour du système

```bash
sudo dnf update -y
```

#### Installation du groupe de virtualisation

```bash
sudo dnf install -y @virtualization
```

Ce groupe installe :

- `qemu-kvm` (QEMU + KVM)
- `libvirt` (daemon et bibliothèques)
- `libvirt-client` (outils CLI)
- `virt-install` (création de VMs)
- `virt-viewer` (console graphique)

#### Installation de `virt-manager` (optionnel)

```bash
sudo dnf install -y virt-manager
```

#### Vérification du support KVM

```bash
lsmod | grep kvm
```

**Résultat attendu** (Intel) :

```
kvm_intel             380928  0
kvm                  1036288  1 kvm_intel
```

**Résultat attendu** (AMD) :

```
kvm_amd               139264  0
kvm                  1036288  1 kvm_amd
```

* * *

## **Étape 3 : Activer le service libvirt**

1.  **Activer et démarrer le service** :

```bash
 sudo systemctl enable --now libvirtd
```

2.  **Vérifier le statut** :

```bash
 sudo systemctl status libvirtd
```

**Résultat attendu** : `Active: active (running)`. 3. **Vérifier la socket** :

```bash
 ls -la /run/libvirt/libvirt-sock
```

> **Pour les distributions modernes** (RHEL 9+, Fedora 34+, openSUSE) :  
> Utilisez des **démons modulaires** :
> 
> ```bash
> sudo systemctl enable --now virtqemud.socket virtnetworkd.socket virtstoraged.socket
> ```

* * *

## **Étape 4 : Configurer les permissions**

Par défaut, seul `root` peut gérer les VMs. Ajoutez votre utilisateur aux groupes `libvirt` et `kvm` :

### Pour **Debian/Ubuntu**

```bash
sudo usermod -aG libvirt,kvm $USER
newgrp libvirt  # Active le groupe dans le terminal courant
```

### Pour **RHEL/Rocky/Fedora**

```bash
sudo usermod -aG libvirt $USER
newgrp libvirt
```

> **Important** :
> 
> - Les changements de groupe nécessitent une **déconnexion/reconnexion**.
> - Pour vérifier les groupes actifs : `id`.

* * *

## **Étape 5 : Configurer l’URI par défaut**

Libvirt utilise deux modes :

- `**qemu:///system**` (pour les serveurs)
- `**qemu:///session**` (pour les environnements desktop).

**Solution recommandée** (pour les serveurs) :

```bash
# Ajouter à ~/.bashrc ou ~/.zshrc
echo 'export LIBVIRT_DEFAULT_URI="qemu:///system"' >> ~/.bashrc
source ~/.bashrc
```

**Vérification** :

```bash
virsh uri  # Doit afficher : qemu:///system
```

* * *

## **Étape 6 : Valider l’installation**

### Test 1 : Lister les VMs

```bash
virsh list --all  # Si LIBVIRT_DEFAULT_URI est configuré
# ou
virsh -c qemu:///system list --all
```

**Résultat attendu** (installation fraîche) :

```
 Id   Name   State
--------------------
```

> Une liste vide est normale (aucune VM créée).

> **Erreur `Permission denied` ?**
> 
> 1.  Vérifiez que vous êtes dans le groupe `libvirt` : `id | grep libvirt`.
> 2.  Si non, **déconnectez-vous et reconnectez-vous**.
> 3.  En attendant, utilisez `sudo`.

* * *

### Test 2 : Vérifier le réseau par défaut

```bash
virsh net-list --all
```

**Résultat attendu** :

```
 Name      State    Autostart   Persistent
--------------------------------------------
 default   active   yes         yes
```

> **Si le réseau `default` est inactif** :
> 
> ```bash
> virsh net-start default
> virsh net-autostart default
> ```

| Distribution | Paquet responsable | Comportement |
| --- | --- | --- |
| Ubuntu/Debian | `libvirt-daemon-config-network` | Crée `default` + `virbr0` automatiquement |
| RHEL/Rocky | Inclus dans `@virtualization` | Crée `default` au démarrage de libvirtd |

* * *

### Test 3 : Vérifier (et créer) le pool de stockage

```bash
virsh pool-list --all
```

**Si le pool `default` est absent** :

```bash
# Créer le pool (pointe vers /var/lib/libvirt/images/)
virsh pool-define-as default dir --target /var/lib/libvirt/images
sudo mkdir -p /var/lib/libvirt/images
virsh pool-start default
virsh pool-autostart default
```

**Résultat attendu** :

```
 Name      State    Autostart
-------------------------------
 default   active   yes
```

* * *

### Test 4 : Validation complète

```bash
virt-host-validate
```

**Exemple de résultat** :

```
QEMU: Checking for hardware virtualization      : PASS
QEMU: Checking if device /dev/kvm exists        : PASS
QEMU: Checking if device /dev/kvm is accessible : PASS
QEMU: Checking if device /dev/vhost-net exists  : PASS
QEMU: Checking if device /dev/net/tun exists    : PASS
QEMU: Checking for cgroup 'memory' controller   : PASS
QEMU: Checking for device assignment IOMMU      : WARN (...)
QEMU: Checking for secure guest support         : WARN (...)
```

| Résultat | Signification |
| --- | --- |
| **PASS** | Fonctionnalité disponible |
| **WARN** | Fonctionnalité optionnelle absente |
| **FAIL** | Problème bloquant à corriger |

> Les **WARN** pour IOMMU ou Secure Guest ne bloquent pas l’usage basique.

* * *

## **Récapitulatif des fichiers importants**

| Chemin | Contenu |
| --- | --- |
| `/etc/libvirt/` | Configuration libvirt |
| `/etc/libvirt/qemu/` | Définitions XML des VMs |
| `/var/lib/libvirt/images/` | Disques virtuels (pool default) |
| `/run/libvirt/libvirt-sock` | Socket de communication |
| `/var/log/libvirt/qemu/` | Logs des VMs |

* * *

## **Erreurs fréquentes**

| Erreur | Cause probable | Solution |
| --- | --- | --- |
| `Permission denied` sur socket | Groupe `libvirt` non actif | Se déconnecter/reconnecter ou `newgrp libvirt` |
| `/dev/kvm` n’existe pas | Virtualisation désactivée | Activer VT-x/AMD-V dans le BIOS |
| `virsh net-list` vide | Connecté à `qemu:///session` | Utiliser `virsh -c qemu:///system` |
| `libvirtd` inactif/n’existe pas | Service non démarré | `systemctl enable --now libvirtd` |

* * *

## **À retenir**

1.  **Vérifier le CPU** : `egrep -c '(vmx|svm)' /proc/cpuinfo` (doit être > 0).
2.  **Installer les paquets** :

- Debian : `qemu-kvm`, `libvirt-daemon-system`, `virtinst`.
- RHEL : `@virtualization`.

3.  **Activer libvirt** : `systemctl enable --now libvirtd`.
4.  **Configurer les permissions** : `usermod -aG libvirt,kvm $USER` + **se reconnecter**.
5.  **Valider** : `virt-host-validate` ( `/dev/kvm` doit être **PASS**).
