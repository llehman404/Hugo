# Créer une VM KVM : virt-manager et virt-install

**Objectif** : Créer une VM fonctionnelle avec KVM/libvirt en moins de 10 minutes, via **virt-manager** (interface graphique) ou **virt-install** (ligne de commande).

---

## 📌 Prérequis

- KVM/libvirt installé et fonctionnel.
- Réseau `default` actif :
  ```bash
  virsh net-list
  ```
  → Doit afficher `default` en **active**.
- Pool de stockage configuré :
  ```bash
  virsh pool-list
  ```
  → Doit afficher `default` en **active**.
- **Image ISO** d'installation (ex: Ubuntu Server 24.04, Debian, Rocky Linux).  
*Liens officiels* :
  - [Ubuntu Server](https://ubuntu.com/download/server)
  - [Debian](https://www.debian.org/download)
  - [Rocky Linux](https://rockylinux.org/download)
  - [Fedora Server](https://fedoraproject.org/server/download)

---

## 🎯 Ce que vous allez apprendre

- Créer une VM avec **virt-manager** (workflow visuel).
- Créer une VM avec **virt-install** (workflow CLI, scriptable).
- Choisir entre **BIOS** et **UEFI**.
- Configurer CPU, RAM, disque, réseau.

### 🖥️ Méthode 1 : virt-manager (Interface Graphique)

**Pour qui** : Débutants, homelab, gestion visuelle.  
**Avantages** : Intuitif, accès facile aux consoles graphiques.

#### 1. Lancer virt-manager

```bash
virt-manager
```

*Pour un serveur distant (SSH avec X11 forwarding)* :

```bash
ssh -X user@serveur
virt-manager
```

#### 2. Créer une VM pas à pas

1. **Nouvelle VM** :
  `File → New Virtual Machine` (ou icône ➕).
2. **Source d'installation** :
  - Sélectionner **Local install media (ISO image or CDROM)**.
  - Cliquer **Forward**.
3. **Sélectionner l'ISO** :
  - Cliquer **Browse → Browse Local**.
  - Naviguer jusqu'au fichier ISO.
  - *Astuce* : Si non détecté, désactiver *"Automatically detect"* et choisir manuellement l'OS.
4. **Configurer CPU et RAM** :
  - **RAM** : 2048 MB (recommandé pour un lab) / 4096+ MB (production).
  - **vCPUs** : 2 (lab) / 4+ (production).
5. **Configurer le disque** :
  - Cocher **Enable storage for this virtual machine**.
  - Taille : **20 GB** (minimum) / 40+ GB (production).
  - *Emplacement* : Disque créé dans le pool `default` (`/var/lib/libvirt/images/`).
6. **Nom et réseau** :
  - **Nom** : `ubuntu-test` (ou personnalisé).
  - Cocher **Customize configuration before install** pour ajuster le firmware (UEFI).
  - Cliquer **Finish**.
7. **Personnalisation (optionnel)** :
  - **Overview → Firmware** : Choisir **UEFI** (OVMF) pour un boot moderne.
  - **NIC** : Vérifier que le réseau est `default` (NAT).
  - Cliquer **Begin Installation**.
8. **Installation** :
  - La console graphique s'ouvre → Suivre l'assistant d'installation de l'OS.

#### ⚖️ BIOS vs UEFI

- **BIOS (SeaBIOS)** : Compatibilité maximale, VMs legacy.
- **UEFI (OVMF)** : OS modernes, Secure Boot, Windows 11.  
*Par défaut, virt-manager utilise BIOS. Pour UEFI, personnaliser la VM avant l'installation.*

### 💻 Méthode 2 : virt-install (Ligne de Commande)

**Pour qui** : Sysadmins, automatisation, serveurs distants (SSH).  
**Avantages** : Scriptable, reproductible, pas besoin de X11.

#### 📜 Syntaxe de base

```bash
virt-install \
  --name <nom> \
  --memory <MB> \
  --vcpus <nombre> \
  --disk <options> \
  --network <options> \
  --cdrom <chemin-iso> \
  --os-variant <type>
```

#### 🔹 Exemple complet : VM Ubuntu avec ISO

```bash
virt-install \
  --name ubuntu-test \
  --memory 2048 \
  --vcpus 2 \
  --disk size=20,format=qcow2,pool=default \
  --network network=default \
  --cdrom /var/lib/libvirt/images/ubuntu-24.04-live-server-amd64.iso \
  --os-variant ubuntu24.04 \
  --graphics vnc,listen=0.0.0.0 \
  --noautoconsole
```

*Copier l'ISO dans le pool* :

```bash
sudo cp ~/Downloads/ubuntu-24.04-live-server-amd64.iso /var/lib/libvirt/images/
```

##### 🔍 Décryptage des options

- `--name ubuntu-test` : Nom de la VM dans libvirt.
- `--memory 2048` : 2 GB de RAM.
- `--vcpus 2` : 2 vCPUs.
- `--disk size=20,format=qcow2,pool=default` : Disque 20 GB (QCOW2) dans le pool `default`.
- `--network network=default` : Réseau NAT.
- `--cdrom /chemin/...` : ISO d'installation.
- `--os-variant ubuntu24.04` : Optimisations pour Ubuntu 24.04.
- `--graphics vnc` : Console VNC (pour virt-manager).
- `--noautoconsole` : Ne pas ouvrir la console automatiquement.

#### 🔹 Lister les `os-variant` disponibles

```bash
virt-install --osinfo list | grep -i ubuntu
```

*Exemple de sortie* :

```
ubuntu25.10, ubuntuquesting
ubuntu24.04, ubuntunoble
ubuntu22.04, ubuntujammy
...
```

*Rechercher pour Debian ou RHEL* :

```bash
virt-install --osinfo list | grep -i debian
virt-install --osinfo list | grep -i rhel
```

#### 🔹 Variante : VM avec boot UEFI

```bash
virt-install \
  --name ubuntu-uefi \
  --memory 2048 \
  --vcpus 2 \
  --disk size=20,format=qcow2,pool=default \
  --network network=default \
  --cdrom /var/lib/libvirt/images/ubuntu-24.04-live-server-amd64.iso \
  --os-variant ubuntu24.04 \
  --boot uefi \
  --graphics vnc \
  --noautoconsole
```

*L'option `--boot uefi` utilise OVMF si installé.*

> ⚠️ **Warning RAM** :  
> Si vous voyez :
>
> ```bash
> WARNING  Requested memory 2048 MiB is less than the recommended 3072 MiB for OS ubuntu24.04
> ```
>
> → C'est un avertissement (pas une erreur). 2 GB suffisent pour un lab, mais prévoyez 3-4 GB pour un usage réel.

#### 🔹 Variante : VM serveur sans interface graphique

```bash
virt-install \
  --name ubuntu-server \
  --memory 2048 \
  --vcpus 2 \
  --disk size=20,format=qcow2,pool=default \
  --network network=default \
  --location https://releases.ubuntu.com/24.04/ubuntu-24.04-live-server-amd64.iso \
  --os-variant ubuntu24.04 \
  --graphics none \
  --console pty,target_type=serial \
  --extra-args 'console=ttyS0,115200n8'
```

*Différences* :

- `--location` au lieu de `--cdrom` : Permet d'injecter des paramètres kernel.
- `--graphics none` : Pas de console graphique.
- `--console pty,target_type=serial` : Console série.
- `--extra-args 'console=ttyS0'` : Redirige la sortie vers la console série.

*Accès à la VM* :

```bash
virsh console ubuntu-server
# Pour sortir : Ctrl+]
```

#### 🔹 Variante : VM connectée à un bridge

```bash
virt-install \
  --name ubuntu-bridge \
  --memory 2048 \
  --vcpus 2 \
  --disk size=20,format=qcow2,pool=default \
  --network bridge=br0 \
  --cdrom /var/lib/libvirt/images/ubuntu-24.04-live-server-amd64.iso \
  --os-variant ubuntu24.04 \
  --graphics vnc \
  --noautoconsole
```

→ La VM obtiendra une IP directement sur votre LAN.

#### 🔹 Variante : Import d'une image cloud (sans installation)

1. **Télécharger l'image cloud** :
  ```bash
   cd /var/lib/libvirt/images
   sudo wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
  ```
2. **Créer un disque basé sur l'image** :
  ```bash
   sudo qemu-img create -f qcow2 -F qcow2 \
     -b /var/lib/libvirt/images/noble-server-cloudimg-amd64.img \
     /var/lib/libvirt/images/ubuntu-test.qcow2 20G
  ```
3. **Créer la VM avec `--import**` :
  ```bash
   virt-install \
     --name ubuntu-test \
     --memory 2048 \
     --vcpus 2 \
     --disk /var/lib/libvirt/images/ubuntu-test.qcow2 \
     --network network=default \
     --os-variant ubuntu24.04 \
     --import \
     --graphics vnc \
     --noautoconsole
  ```

> ⚠️ **Image cloud = pas de mot de passe** :  
> Les images cloud n'ont pas de mot de passe par défaut. Utilisez **cloud-init** pour configurer l'accès SSH.

## 🛠️ Après la création : Commandes utiles

### Lister les VMs

```bash
virsh list --all
```

*Exemple de sortie* :

```
 Id   Name          State
-----------------------------
 1    ubuntu-test   running
```

### Accéder à la console

- **Console graphique** (via virt-manager) :
  ```bash
  virt-viewer ubuntu-test
  ```
- **Console série** (si configurée) :
  ```bash
  virsh console ubuntu-test
  # Pour sortir : Ctrl+]
  ```

### Démarrer / Arrêter

```bash
# Démarrer
virsh start ubuntu-test

# Arrêter proprement (ACPI shutdown)
virsh shutdown ubuntu-test

# Arrêt forcé (équivalent couper le courant)
virsh destroy ubuntu-test
```

### Voir les informations

```bash
virsh dominfo ubuntu-test
```

*Exemple de sortie* :

```
Id:             1
Name:           ubuntu-test
UUID:           09978674-04a9-4f02-a61f-18615ddedca1
OS Type:        hvm
State:          running
CPU(s):         2
Max memory:     2097152 KiB
Used memory:    2097152 KiB
Persistent:     yes
Autostart:      disable
```

### Activer le démarrage automatique

```bash
virsh autostart ubuntu-test
```

## ❌ Erreurs fréquentes et solutions


| **Erreur**                    | **Cause**                | **Solution**                                                         |
| ----------------------------- | ------------------------ | -------------------------------------------------------------------- |
| `ERROR: --os-variant unknown` | `os-variant` incorrect   | Lister avec `virt-install --osinfo list`                             |
| `Permission denied` sur l'ISO | ISO non lisible par QEMU | `chmod 644` ou déplacer dans `/var/lib/libvirt/images/`              |
| `Cannot access storage`       | Pool non démarré         | `virsh pool-start default`                                           |
| `Network not found`           | Réseau `default` inactif | `virsh net-start default`                                            |
| `Unable to complete install`  | RAM insuffisante         | Augmenter `--memory`                                                 |
| `UEFI firmware not found`     | OVMF non installé        | `apt install ovmf` (Debian/Ubuntu) ou `dnf install edk2-ovmf` (RHEL) |


> 💡 **ISO dans `/home` non accessible** :  
> Par défaut, QEMU s'exécute en tant qu'utilisateur `libvirt-qemu` (pas d'accès à `/home`).  
> **Solutions** :
>
> 1. Copier l'ISO dans `/var/lib/libvirt/images/`.
> 2. Ajouter les permissions :
>   ```bash
>    setfacl -m u:libvirt-qemu:rx /home/$USER
>   ```

## ✅ Checklist création VM

- ISO téléchargée et accessible.
- Pool de stockage actif (`virsh pool-list`).
- Réseau actif (`virsh net-list`).
- Ressources disponibles (RAM, espace disque).
- `os-variant` correct pour l'OS cible.
- Mode boot choisi (BIOS ou UEFI).

## 🔑 À retenir

1. **virt-manager** = Interface graphique, idéale pour découvrir et gérer un homelab.
2. **virt-install** = Ligne de commande, idéale pour l'automatisation et les scripts.
3. **Options essentielles** :
  `--name`, `--memory`, `--vcpus`, `--disk`, `--network`, `--cdrom`/`--location`.
4. `**os-variant**` : Active les optimisations pour l'OS cible → Toujours le spécifier.
5. **UEFI** (`--boot uefi`) : Pour les OS modernes. BIOS par défaut pour la compatibilité.
6. **Console série** (`--graphics none --console pty`) : Pour les serveurs headless.
