# Bridge KVM sans NetworkManager (Debian/Ubuntu ifupdown)

> **Guide pour créer un bridge avec `ifupdown` sur Debian ou Ubuntu Server, sans utiliser NetworkManager.**  
> *Idéal pour connecter vos VMs directement au LAN.*

---

## **⚠️ Prérequis et Avertissements**

- **Debian 11+** ou **Ubuntu Server 20.04+**.
- **Pas de NetworkManager** (vérifiez avec `systemctl status NetworkManager`).
- **Accès root**.
- **⚠️ Risque de perte d'accès SSH** : Ayez toujours un **accès console** (IPMI, KVM physique) en cas d'erreur.

---

---

## **🔍 Étape 1 : Identifier la configuration actuelle**

### **Lister les interfaces réseau**

```bash
# Lister les interfaces et leurs IPs
ip addr show

# Lister uniquement les interfaces (sans loopback)
ip -br link | grep -v lo
```

> **À noter** :
>
> - Nom de l'**interface physique** (ex: `eno1`, `enp3s0`, `eth0`).
> - **IP actuelle** (ex: `192.168.1.100/24`).
> - **Passerelle (gateway)** (ex: `192.168.1.1`).

---

---

## **💾 Étape 2 : Sauvegarder la configuration actuelle**

```bash
sudo cp /etc/network/interfaces /etc/network/interfaces.backup
```

> **Pourquoi ?**  
> En cas d'erreur, tu pourras restaurer la configuration d'origine.

---

---

## **🌉 Étape 3 : Créer le bridge**

### **1. Installer `bridge-utils` (si nécessaire)**

```bash
sudo apt update
sudo apt install bridge-utils
```

---

### **2. Éditer `/etc/network/interfaces**`

Ouvre le fichier avec `nano` ou ton éditeur préféré :

```bash
sudo nano /etc/network/interfaces
```

#### **Configuration pour une IP statique**

Remplace le contenu par :

```ini
# Loopback (interface locale)
auto lo
iface lo inet loopback

# Interface physique : désactivée (esclave du bridge)
auto eno1
iface eno1 inet manual

# Bridge avec IP statique
auto br0
iface br0 inet static
    address 192.168.1.100      # Remplace par ton IP
    netmask 255.255.255.0      # Remplace par ton masque
    gateway 192.168.1.1        # Remplace par ta passerelle
    dns-nameservers 8.8.8.8 1.1.1.1  # DNS Google et Cloudflare
    bridge_ports eno1         # Remplace par ton interface physique
    bridge_stp off            # Désactive le Spanning Tree Protocol (inutile pour un bridge simple)
    bridge_fd 0               # Désactive le forward delay
```

#### **Configuration pour une IP en DHCP**

Si tu préfères obtenir une IP automatiquement :

```ini
# Loopback
auto lo
iface lo inet loopback

# Interface physique : désactivée
auto eno1
iface eno1 inet manual

# Bridge avec DHCP
auto br0
iface br0 inet dhcp
    bridge_ports eno1
    bridge_stp off
    bridge_fd 0
```

---

### **3. Appliquer la configuration**

#### **Méthode 1 (recommandée pour systemd)**

```bash
sudo systemctl restart networking
```

#### **Méthode 2 (pour les anciennes versions)**

```bash
sudo ifdown eno1 && sudo ifup br0
```

---

### **4. Vérifier la configuration**

#### **Vérifier que le bridge a bien l'IP**

```bash
ip addr show br0
```

**Sortie attendue** :

```
3: br0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc noqueue state UP group default qlen 1000
    link/ether xx:xx:xx:xx:xx:xx brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.100/24 brd 192.168.1.255 scope global br0
       valid_lft forever preferred_lft forever
```

#### **Vérifier que l'interface physique est dans le bridge**

```bash
bridge link show
```

**Sortie attendue** :

```
2: eno1: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 master br0 state forwarding priority 32 cost 2
```

#### **Tester la connectivité**

```bash
ping -c 2 192.168.1.1    # Passerelle
ping -c 2 8.8.8.8        # Internet
```

## **🔌 Étape 4 : Connecter une VM au bridge**

### **Avec `virt-install**`

```bash
virt-install \
  --name ma-vm \
  --memory 2048 \
  --vcpus 2 \
  --disk path=/var/lib/libvirt/images/ma-vm.qcow2,size=10 \
  --network bridge=br0 \  # Utilise le bridge br0
  --os-type linux \
  --os-variant ubuntu22.04
```

### **Dans le XML de la VM**

Si tu définis ta VM via un fichier XML (pour `virsh define`) :

```xml
<interface type='bridge'>
  <source bridge='br0'/>
  <model type='virtio'/>
</interface>
```

## **🔄 Étape 5 : Restaurer en cas de problème**

Si tu perds l'accès SSH (à cause d'une erreur de configuration), **depuis la console** (IPMI, KVM physique) :

```bash
sudo cp /etc/network/interfaces.backup /etc/network/interfaces
sudo systemctl restart networking
```

## **🌟 Variantes avancées**

---

### **1. Bridge avec VLAN**

Si tu veux que le bridge soit sur un **VLAN spécifique** (ex: VLAN 100) :

```ini
# Interface physique
auto eno1
iface eno1 inet manual

# Sous-interface VLAN
auto eno1.100
iface eno1.100 inet manual
    vlan-raw-device eno1

# Bridge sur le VLAN
auto br0
iface br0 inet static
    address 192.168.100.10
    netmask 255.255.255.0
    gateway 192.168.100.1
    bridge_ports eno1.100
    bridge_stp off
    bridge_fd 0
```

---

### **2. Plusieurs bridges**

Pour isoler différents groupes de VMs (ex: un bridge pour le LAN, un autre pour un lab interne) :

```ini
# Bridge 1 : connecté au LAN
auto br0
iface br0 inet static
    address 192.168.1.100
    netmask 255.255.255.0
    gateway 192.168.1.1
    bridge_ports eno1
    bridge_stp off
    bridge_fd 0

# Bridge 2 : isolé (pour un lab interne)
auto br1
iface br1 inet static
    address 10.0.0.1
    netmask 255.255.255.0
    bridge_ports none      # Pas d'interface physique
    bridge_stp off
    bridge_fd 0
```

> **Cas d'usage pour `br1**` :
>
> - Réseau interne pour des VMs qui communiquent entre elles **sans accès au LAN ou à Internet**.
> - Idéal pour des labs de test ou des environnements isolés.

## **❓ FAQ**

### **Pourquoi désactiver le STP (`bridge_stp off`) ?**

Le **Spanning Tree Protocol (STP)** est utile pour éviter les boucles dans les réseaux complexes (ex: avec plusieurs switches). Pour un **bridge simple sur un seul hôte**, il est inutile et peut causer des délais inutiles (`forwardDelay`). Désactiver `stp` et `fd` accélère la mise en place du bridge.

---

### **Pourquoi `bridge_fd 0` ?**

`bridge_fd` (Forward Delay) est le temps pendant lequel le bridge attend avant de commencer à transférer des paquets. Avec `0`, le bridge est opérationnel immédiatement.

---

### **Puis-je utiliser ce guide sur Ubuntu Desktop ?**

Oui, mais **NetworkManager** est souvent actif par défaut sur Ubuntu Desktop. Dans ce cas :

1. Désactive NetworkManager :
  ```bash
   sudo systemctl stop NetworkManager
   sudo systemctl disable NetworkManager
  ```
2. Active le service `networking` :
  ```bash
   sudo systemctl enable --now networking
  ```
3. Suis ensuite les étapes de ce guide.

---

### **Comment ajouter une deuxième interface physique au bridge ?**

Modifie la ligne `bridge_ports` dans `/etc/network/interfaces` :

```ini
bridge_ports eno1 enp3s0  # Remplace par tes interfaces
```
