# Installer Nix sur Linux : mode single-user et multi-user

#nix #linux #installation

---

L’installation de **[Nix](https://blog.stephane-robert.info/docs/admin-serveurs/linux/nix/)** prend moins de 5 minutes et ne modifie rien en dehors du répertoire `/nix`. Vous pouvez l’installer sur **Debian**, **Ubuntu**, **Fedora**, **Arch** ou toute distribution [Linux](https://blog.stephane-robert.info/docs/admin-serveurs/linux/) — et le désinstaller proprement si besoin.

Ce guide couvre :

- Les deux modes d’installation (single-user et multi-user).
- La configuration initiale des commandes modernes et des flakes.
- Un premier test pour vérifier que tout fonctionne.

---

## Ce que vous allez apprendre

- **Choisir** entre l’installation *single-user* et *multi-user* selon votre contexte.
- **Installer Nix** sur votre distribution Linux en une commande.
- **Activer les commandes modernes** (`nix shell`, `nix profile`, `nix search`) et les **flakes**.
- **Vérifier** que l’installation fonctionne avec un premier paquet temporaire.
- **Désinstaller Nix** proprement si nécessaire.

---

## Dans quel contexte ?

Vous avez lu le guide sur l’écosystème Nix et vous voulez passer à la pratique. Voici les situations typiques :

- Vous administrez un serveur Debian ou Ubuntu et vous voulez tester Nix **sans toucher** à votre installation [apt](https://blog.stephane-robert.info/docs/admin-serveurs/linux/apt/) existante.
- Vous développez sur plusieurs projets qui ont besoin de versions différentes de [Python](https://blog.stephane-robert.info/docs/developper/programmation/python/), Node.js ou [Terraform](https://blog.stephane-robert.info/docs/infra-as-code/provisionnement/terraform/).
- Vous préparez un environnement **reproductible** pour votre équipe.
- Vous êtes sur un poste partagé et vous avez besoin d’**isoler vos paquets**.

## Prérequis

- Un système Linux avec **accès root** ([sudo](https://blog.stephane-robert.info/docs/admin-serveurs/linux/sudo/)).
- **[curl](https://blog.stephane-robert.info/docs/admin-serveurs/linux/curl/)** installé (présent par défaut sur la plupart des distributions).
- Au moins **5 [Go](https://blog.stephane-robert.info/docs/developper/programmation/golang/)** d’espace disque disponible pour `/nix`.
- Une connexion Internet.

**Vérifiez que `curl` est disponible :**

```bash
which curl || sudo apt install curl  # Debian/Ubuntu
```

## Choisir entre single-user et multi-user

Nix propose deux modes d’installation. Le choix dépend de votre usage.


| Critère                   | Single-user                     | Multi-user                            |
| ------------------------- | ------------------------------- | ------------------------------------- |
| **Daemon**                | Non                             | Oui (`nix-daemon`)                    |
| **Isolation**             | Pas de séparation de privilèges | Builds isolés dans des comptes dédiés |
| **Utilisateurs**          | Un seul                         | Plusieurs                             |
| **Recommandé pour**       | Tests rapides, poste personnel  | Serveurs, postes partagés, production |
| **Droits pour installer** | Utilisateur courant             | Root (pour le daemon)                 |


**Quel mode choisir ?**  
En cas de doute, prenez le **multi-user**. C’est le mode recommandé par l’équipe Nix. Il est plus sécurisé (les builds tournent dans des comptes dédiés `nixbld*`) et c’est celui utilisé dans tous les guides de cette section.

---

## Installer Nix en mode single-user

Le mode *single-user* est le plus simple. Nix s’installe dans `/nix` et fonctionne directement sous votre utilisateur, sans daemon.

```bash
sh <(curl -L https://nixos.org/nix/install) --no-daemon
```

1. L’installateur télécharge Nix et crée le répertoire `/nix/store/`.
2. Il configure votre shell en ajoutant une ligne dans `~/.profile` ou `~/.bashrc`.
3. Les commandes Nix deviennent accessibles dans votre `PATH`.

**Nouveau terminal requis**  
Après l’installation, **ouvrez un nouveau terminal** pour que le `PATH` soit mis à jour. Sinon, exécutez manuellement :

```bash
. ~/.nix-profile/etc/profile.d/nix.sh
```

---

## Installer Nix en mode multi-user

Le mode *multi-user* crée un daemon système (`nix-daemon`) et un groupe de comptes dédiés (`nixbld1` à `nixbld32`) pour isoler les builds.

```bash
sh <(curl -L https://nixos.org/nix/install) --daemon
```

L’installateur vous pose quelques questions. Répondez **yes** à chaque fois pour accepter les valeurs par défaut.

1. L’installateur crée le répertoire `/nix/store/` et les comptes `nixbld*`.
2. Il installe et démarre le service `nix-daemon.service`.
3. Il configure `/etc/profile.d/nix-daemon.sh` pour que tous les utilisateurs aient Nix dans leur `PATH`.

**Vérifiez que le daemon tourne :**

```bash
systemctl status nix-daemon.service
```

**Sortie attendue :**

```
● nix-daemon.service - Nix Daemon
     Loaded: loaded (/etc/systemd/system/nix-daemon.service; linked; preset: enabled)
     Active: active (running)
   Main PID: 2383 (nix-daemon)
```

## Alternative : le Determinate Nix Installer

Le **Determinate Nix Installer** (maintenu par Determinate Systems) est une alternative à l’installateur officiel. Il installe toujours en *multi-user*, active les flakes par défaut, et fournit une désinstallation propre.

```bash
curl --proto '=https' --tlsv1.2 -sSf -L https://install.determinate.systems/nix | sh -s -- install
```

**Installateur officiel vs Determinate**

- L’installateur officiel est maintenu par l’équipe Nix.
- Le Determinate Installer est un projet tiers mais très populaire dans la communauté [DevOps](https://blog.stephane-robert.info/docs/devops/fondamentaux/).
- Les deux produisent une installation fonctionnelle.
- **Ce guide utilise l’installateur officiel.**

## Vérifier l’installation

Ouvrez un nouveau terminal (ou sourcez le profil manuellement) et testez :

```bash
nix --version
```

**Sortie attendue :**

```
nix (Nix) 2.34.6
```

**Vérifiez également que le store est accessible :**

```bash
nix store info
```

**Sortie attendue :**

```
Store URL: daemon
Version: 2.34.6
Trusted: 1
```

`Trusted: 1` confirme que votre utilisateur est reconnu par le daemon Nix.

## Activer les commandes modernes et les flakes

Par défaut, certaines commandes Nix modernes (`nix shell`, `nix profile`, `nix search`, `nix develop`) et les **flakes** sont désactivées car elles sont encore considérées comme expérimentales par l’équipe Nix — même si la communauté les utilise massivement.

**Créez ou éditez le fichier `/etc/nix/nix.conf` :**

```bash
sudo mkdir -p /etc/nix
sudo tee /etc/nix/nix.conf > /dev/null << 'EOF'
experimental-features = nix-command flakes
sandbox = true
EOF
```

**Puis redémarrez le daemon :**

```bash
sudo systemctl restart nix-daemon.service
```

**Vérifiez que la configuration est prise en compte :**

```bash
cat /etc/nix/nix.conf
```

**Sortie attendue :**

```
experimental-features = nix-command flakes
sandbox = true
```

**Que sont ces *features* ?**

- `**nix-command**` : Active l’interface CLI unifiée (`nix shell`, `nix profile`, `nix search`, `nix build`…) qui remplace les anciennes commandes séparées (`nix-env`, `nix-shell`, `nix-build`).
- `**flakes**` : Active le système de dépendances avec *lock file* qui garantit la reproductibilité (`flake.nix` + `flake.lock`).

## Configurer votre shell

### Bash et Zsh

En *multi-user*, l’installateur crée automatiquement `/etc/profile.d/nix-daemon.sh` qui est sourcé au login. Si les commandes Nix ne sont pas disponibles après connexion, ajoutez dans votre `~/.bashrc` ou `~/.zshrc` :

```bash
# Charger Nix
if [ -e /nix/var/nix/profiles/default/etc/profile.d/nix-daemon.sh ]; then
  . /nix/var/nix/profiles/default/etc/profile.d/nix-daemon.sh
fi
```

### Fish

Pour [Fish shell](https://blog.stephane-robert.info/docs/admin-serveurs/linux/shells-linux/fish/), ajoutez dans `~/.config/fish/config.fish` :

```bash
# Charger Nix
if test -e /nix/var/nix/profiles/default/etc/profile.d/nix.fish
  source /nix/var/nix/profiles/default/etc/profile.d/nix.fish
end
```

## Tester avec un premier paquet temporaire

Vérifions que Nix fonctionne de bout en bout en exécutant un paquet **sans l’installer** :

```bash
nix run nixpkgs#cowsay -- 'Nix fonctionne !'
```

**La première exécution télécharge les dépendances depuis le cache binaire :**

```
 __________________
< Nix fonctionne ! >
 ------------------
        \   ^__^
         \  (oo)\_______
            (__)\       )\/\
                ||----w |
                ||     ||
```

Le paquet `cowsay` n’est **pas installé** dans votre profil. Il a été téléchargé dans le store (`/nix/store/`) et exécuté une seule fois. Vous pouvez le vérifier :

```bash
which cowsay
# cowsay not found — il n'est pas dans votre PATH
```

C’est l’une des forces de Nix : **tester un outil en une commande, sans polluer votre système.**

## Désinstaller Nix proprement

Si vous voulez retirer Nix de votre système :

### Multi-user

1. **Arrêtez le daemon :**
  ```bash
   sudo systemctl stop nix-daemon.service
   sudo systemctl disable nix-daemon.socket nix-daemon.service
  ```
2. **Supprimez les fichiers Nix :**
  ```bash
   sudo rm -rf /nix /etc/nix
   sudo rm -f /etc/profile.d/nix-daemon.sh
  ```
3. **Supprimez les comptes et le groupe :**
  ```bash
   for i in $(seq 1 32); do sudo userdel "nixbld$i" 2>/dev/null; done
   sudo groupdel nixbld 2>/dev/null
  ```
4. **Nettoyez les fichiers utilisateur :**
  ```bash
   rm -rf ~/.nix-profile ~/.nix-defexpr ~/.nix-channels ~/.local/state/nix
  ```

### Single-user

```bash
rm -rf /nix ~/.nix-profile ~/.nix-defexpr ~/.nix-channels
```

**Retirez aussi la ligne de sourcing** dans `~/.profile`, `~/.bashrc` ou `~/.zshrc`.

## Dépannage courant


| Symptôme                                               | Cause probable                                       | Solution                                                                                                    |
| ------------------------------------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `nix: command not found` après installation            | Shell non rechargé                                   | Ouvrez un nouveau terminal ou sourcez le profil manuellement.                                               |
| `error: getting status of /nix`                        | `/nix` n’existe pas                                  | Relancez l’installateur.                                                                                    |
| `error: cannot connect to daemon`                      | `nix-daemon` arrêté                                  | `sudo systemctl start nix-daemon.service`                                                                   |
| `warning: Nix search path entry...` après `nix search` | Commandes modernes non activées                      | Ajoutez `experimental-features = nix-command flakes` dans `/etc/nix/nix.conf`.                              |
| `permission denied` sur `/nix/store/`                  | Installation *single-user* avec mauvais propriétaire | Vérifiez `ls -la /nix/store/` — le propriétaire doit être votre utilisateur (*single*) ou *root* (*multi*). |

## À retenir

- **Le mode multi-user est recommandé** : il isole les builds dans des comptes dédiés et fonctionne pour tous les utilisateurs du système.
- **Activez `nix-command` et `flakes**` dans `/etc/nix/nix.conf` — c’est indispensable pour suivre les guides de cette section.
- **Nix ne touche rien** en dehors de `/nix` : votre `apt`, votre `dnf` et vos paquets existants restent intacts.
- **Testez avec `nix run nixpkgs#cowsay**` pour vérifier que tout fonctionne de bout en bout.
- **La désinstallation est propre** : supprimer `/nix` et les fichiers de configuration suffit.
