# Présentation des trois couche de virtualisation sous linux

## KVM

KVM est un module d’un noya Linux. C’est une extension du kernel qui a été développé pour transformé le noyaux linux en hyperviseur1.

***Ce que fait KVM***

- **Accélération matérielle**: utilise les instructions CPU (Intel VT-x / AMD-V) pour exécuter les VMs à vitesse quasi-native
- **Isolation** : chaque VMs est isolée des autres grâce au matériel
- **Performance** : les instructions de la VMs s’exécutent directement sur le CPU, pas d’émulation coûteuse

***Ce que ne fait pas kvm***

- **KVM** ne crée pas de VMs
    
- **KVM** ne gère pas les disques virtuels
    
- **KVM** ne configure pas le réseau
    
    KVM est le module que permet à des VMs de tourner de façon native sur linux sans besoins d’émulation avec des performances trés proche du bare-metal.
    

⚠ INTEL VS AMD

- Intel VT -X -> module kvm_Intel
- AMD-V -> module kvm_amd

* * *

## QEMU

QEMU ( Quick Emulator) permet de émuler de de virtualiser. C’est lui qui crée réellement les machines virtuelles.

***Ce que fait QEMU***

- Il crées les VMs en définissant le matériel virtuel (CPU, RAM, disques, cartes réseau)
    
- Il émule le matériel pour différentes architectures (x86, ARM, etc)
    
- Il gère les différent périphériques tels que les disques virtuels, les cartes réseau, USB, etc
    
    | **Mode** | **Performance** | **Usage** | | — | — | — | | QEMU seul | Lente (émulation) | Émuler une autre architecture (ARM sur x86) | | QEMU + KVM | Quasi-native | VMs de production sur même architecture |
    

En pratique, on utilise presque toujours QEMU + KVM pour les VMs Linux/Windows sur serveur x86.

QEMU en direct (rare)

On peut lancer une VMs directement avec QEMU, par exemple qemu-system-x86_64 -enable-kvm -m 2048 …, mais c’est fastidieux à gérer. En pratique, on passe par libvirt. (peux être utile si on veux simuler des architecture différente)

* * *

## libvirt

libvirt est une couche de gestion qui simplifie l’utilisation de QEMU/KVM (et d’autres hyperviseurs).

***Ce que fait libvirt***

- **API unifié**: Elle à la même interface on peux utilisé plusieurs type de logicielle émulation/virtualisation tel que KVM/QEMU, QEMU, Xen, VirtualBox, VMware.
    
- **Daemon**: C’est un daemon, cela signifie qu’il tourne en arrière plan et gère les VMs (pour interagir avec libvirt il faut utilisé systemctl ou service)
    
- **Outils**: Elle est composé de plusieurs Outils comme `virsh` (CLI), `virt-manager` (GUI), `virt-install` (création)
    
- **Configuration**: Elle stocke les définitions des VMs en XML
    

* * *

```
⚠⚠⚠ Attention !!!
```

- Par défaut, libvirt utilise QEMU/KVM (via `qemu:///system` ou `qemu:///session`) si tu ne précises rien.
    
- Pour utiliser par exemple VirtualBox, tu dois explicitement spécifier l’URI de connexion : `vbox:///session` (ou `vbox:///system` pour le mode root).
    
- Exemple avec `virt-install` :
    
    ```bash
    virt-install --connect vbox:///session --name ma-vm-vbox ...
    ```
    

| **Sans libvirt** | **Avec libvirt** |
| --- | --- |
| Commandes QEMU longues et complexes | `virsh start ma-vm` |
| Pas de persistance automatique | VMs définies et persistantes |
| Gestion manuelle du réseau | Réseaux virtuels préconfigurés |
| Pas d’interface graphique | virt-manager, cockpit |

```
Avec libvirt, vous ne parlez pas de *“fichiers QEMU”* ou *“modules kernel”*. Vous manipulez des **objets** avec des noms clairs. Un point fondamental : Un objet (domain, network, pool) peut être :
```

- **Défini** : configuration persistante, stockée sur disque.
    
- **Actif** : en cours d’exécution / disponible.
    

* * *

### Domain (la VM)

- **Quoi ?** Une machine virtuelle, l’objet principal que vous créez et gérez.
- **Pourquoi “domain” ?** Terme hérité de **Xen**. Libvirt l’a conservé pour la compatibilité.
- **Commande** : `virsh list --all` (lister tous les domains, actifs et définis).

### Network (le réseau virtuel)

- **Quoi ?** Un réseau virtuel. Par défaut, libvirt crée un réseau **“default”** en NAT.
- **Commande** : `virsh net-list --all` (lister tous les réseaux).

### Storage Pool et Volume

- **Storage Pool** : Un conteneur de disques (ex: `/var/lib/libvirt/images/`).
- **Volume** : Un disque virtuel individuel (fichier ou LV).
- **Commande** : `virsh pool-list --all` (lister les pools).

* * *

| **Objet libvirt** | **Ce que c’est** | **État “défini”** | **État “actif”** |
| --- | --- | --- | --- |
| Domain | Machine virtuelle | Config XML stockée | VM en cours d’exécution |
| Network | Réseau virtuel | Config réseau stockée | Bridge créé, DHCP actif |
| Storage Pool | Conteneur de disques | Chemin configuré | Accessible pour volumes |
| Volume | Disque virtuel | —   | Fichier/LV existant |

* * *

Quand vous lancez `virsh start ma-vm` :

1.  Vous → Envoyez la commande à libvirt (via `virsh`).
2.  libvirt → Lit la définition XML de la VM, vérifie les ressources.
3.  libvirt → Lance un processus **QEMU** avec les bons paramètres.
4.  QEMU → Crée la VM et demande à **KVM** d’accélérer l’exécution.
5.  KVM → Utilise le CPU pour exécuter les instructions de la VM.

**Résultat** : La VM tourne.
