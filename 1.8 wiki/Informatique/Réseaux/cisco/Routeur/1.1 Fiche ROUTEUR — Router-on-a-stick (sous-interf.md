# Fiche ROUTEUR — Router-on-a-stick (sous-interfaces)

## Le concept

Le routeur est relié au switch par **un seul câble** (trunk), qui transporte **plusieurs VLANs**. Un port physique ne porte qu'une seule IP — donc on le découpe en **sous-interfaces virtuelles**, une par VLAN, chacune avec sa propre IP (la gateway de son réseau).

```text
interface fa0/0          ← port physique (no shutdown, PAS d'IP)
  ├── fa0/0.5            ← VLAN 5 (voix)  → IP 172.16.5.1
  └── fa0/0.10           ← VLAN 10 (data) → IP 172.16.10.1
```

Le switch envoie les trames **taguées 802.1Q** sur le trunk ; chaque sous-interface « trie » les trames de son VLAN grâce à `encapsulation dot1Q`.

## 1. Création / Configuration

```text
Router(config)# interface fa0/0
Router(config-if)# no shutdown          ← sur le PHYSIQUE, obligatoire
Router(config-if)# exit

Router(config)# interface fa0/0.5
Router(config-subif)# encapsulation dot1Q 5
Router(config-subif)# ip address 172.16.5.1 255.255.255.0
Router(config-subif)# exit

Router(config)# interface fa0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 172.16.10.1 255.255.255.0
```

| Commande | Rôle |
|---|---|
| `interface fa0/0.X` | Crée la sous-interface virtuelle. **X est libre** (simple rappel du VLAN), seul le numéro dans `dot1Q` compte |
| `encapsulation dot1Q <vlan>` | Associe la sous-interface au VLAN N. **OBLIGATOIRE avant l'IP** sinon erreur. Doit matcher le VLAN créé sur le switch |
| `ip address <ip> <masque>` | La gateway du réseau de ce VLAN — doit correspondre au `default-router` annoncé par le DHCP |
| `no shutdown` | Uniquement sur l'interface **physique** (une sous-interface est up dès que sa parente l'est) |

> Le routeur n'a **pas** de mode trunk à configurer (`switchport mode trunk` = `% Invalid input` sur un routeur) : le trunk se configure côté switch, le routeur « parle trunk » via ses sous-interfaces.

## 2. Contrôle / Vérification

```text
Router# show ip interface brief      ← fa0/0, fa0/0.5, fa0/0.10 : up/up avec les bonnes IP
Router# show interfaces fa0/0.5       ← détail d'une sous-interface (encapsulation, IP, état)
Router# show running-config          ← vérifier chaque encapsulation dot1Q et chaque IP
Router# ping 172.16.5.11             ← test du routage de bout en bout (client de l'autre VLAN)
```

**Pièges classiques à vérifier :**

1. **Oublier `no shutdown` sur le port physique** → toutes les sous-interfaces down/down
2. **`ip address` avant `encapsulation dot1Q`** → refusé par l'IOS
3. **Numéro dot1Q ≠ numéro du VLAN switch** → sous-interface up mais aucun trafic (gateway fantôme)
4. **IP de sous-interface ≠ `default-router` du DHCP** → les clients ont une gateway que personne ne porte

## 3. Suppression / Modification

```text
Router(config)# no interface fa0/0.5          ← supprime entièrement la sous-interface
Router(config-subif)# no ip address           ← retire seulement l'IP de la sous-interface
Router(config-subif)# encapsulation dot1Q 10  ← modifier : retaper dot1Q avec le nouveau numéro
Router(config-subif)# ip address <nouvelle-ip> 255.255.255.0   ← modifier : retaper l'IP suffit
```

> Pour **modifier** (changer l'IP ou le VLAN d'une sous-interface), inutile de supprimer : retape la commande avec la nouvelle valeur, elle remplace l'ancienne. `no interface fa0/0.X` sert uniquement quand on veut repartir de zéro sur cette sous-interface (elle disparaît du `show run`).
>
> ⚠️ Dans PT, après suppression/création, vérifie avec `show ip interface brief` que l'état voulu est bien pris en compte.

## Schéma logique

```text
                      [Routeur gateway]
                     fa0/0 (trunk, pas d'IP)
                      /            \
               fa0/0.5           fa0/0.10
            dot1Q 5            dot1Q 10
            172.16.5.1         172.16.10.1
                 |                  |
              VLAN 5            VLAN 10
          (voix 172.16.5.0/24)  (data 172.16.10.0/24)
                 |                  |
              Téléphones         PC / serveurs
```
